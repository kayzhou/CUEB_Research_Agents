环境尚未在本机装好时，先跳到 [第二篇](#第二篇从服务器完整迁移到本地windows--macos--linux-原生)。

## 1. 框架是什么

本框架把一篇**理论计量论文**从模型想法到投稿返修的全过程，拆成 **7 个可独立运行的模块**，由 **3 个角色**协作完成。

### 1.1 三角色

| 角色 | 由谁承担 | 职责 | 不可做 |
|------|---------|------|--------|
| **Lead Author** | 你（人类） | 模型创新点、识别逻辑与最终理论结论；**全部卡点裁决** | — |
| **Researcher** | AI（`agents/researcher.md`） | 推导、编码、写作 + 拓展思考 + 回应攻击 | 单方面改模型/定理结论、伪造证明或模拟结果 |
| **Referee** | AI（`agents/referee.md`） | 五视角攻击产出、模拟专家评审 | 写正面内容、代笔修改、空泛批评 |

设计内核是「**反对党无处不在**」：模型设定、假设体系、核心定理、模拟设计、正式审稿等重要产出，在被采纳前都要经过 Referee 攻击和你的裁决。

### 1.2 七模块

理论计量论文的核心产出是**定理与证明**，Monte Carlo 是佐证。模块划分对应自然分工：

```
M1 模型设定 ──→ M2 文献定位 ──→ M3 QML 估计 ──→ M4 渐近理论 ──→ M5 Monte Carlo ──→ M6 论文写作 ──→ M7 审稿返修
  卡点：模型批准     卡点：贡献定位     卡点：估计方案     卡点：假设+定理     卡点：模拟设计     卡点：章节审阅     卡点：意见裁决
```

| 模块 | 名称 | 核心产出 |
|------|------|---------|
| **M1** | 模型设定与似然 | 模型方程、参数空间、QML 对数似然、记号登记表 |
| **M2** | 文献定位与贡献审计 | 文献矩阵、贡献诊断、新颖性风险 |
| **M3** | QML 估计方法 | 目标函数、集中化或 profile、优化算法、标准误方案 |
| **M4** | 渐近理论与证明 | 假设体系、定理地图、证明蓝图与草稿、proof gap |
| **M5** | Monte Carlo 模拟 | DGP + 估计器代码、bias/RMSE/CP 表 |
| **M6** | 论文写作 | LaTeX 全稿（正文 + 附录证明） |
| **M7** | 审稿与返修 | 五视角评审、response 矩阵、终稿一致性检查 |

每个模块由两层文档定义，**编号一一对应**：

- `modules/MX-*/MODULE.md` = **思维框架**（Requires/Produces、卡点、阶段闸门）
- `.cursor/skills/mX-*/SKILL.md` = **执行框架**（具体步骤；Cursor 自动发现）

### 1.3 三种运行方式

| 方式 | 适用场景 | 说明 |
|------|---------|------|
| **A 端到端** | 从一个模型想法开新论文 | M1 → M7 顺序执行 |
| **B 从某步切入** | 部分工作已完成 | 例如证明已写好，只跑 M5 + M6；缺的上游用 stub 补齐 |
| **C 单模块** | 只做一件事 | 例如只用 M4 审查证明、只用 M7 模拟审稿 |

### 1.4 两个支撑系统

- **`paper-lib/`**：用户提供的领域资料入口；实际研究资料放入项目 `literature/library/`，
  引用结论前须回原文核对。
- **工具链**（`ENVIRONMENT.md`）：Python（脚本/RAG/检查）、R（空间计量交叉验证）、TeX Live（论文编译）、MATLAB/Octave/Python（M5 模拟）、Stata/MATLAB（MCP 或本地直连；见 [`本地化部署说明.md`](本地化部署说明.md)）。

## 2. 快速开始（10 分钟跑通）

### 2.1 打开正确的工作区

用 Cursor 打开 **`Theoretical-Econometrics-Agent/` 仓库根目录**，不要只打开 `projects/{slug}/`。
根目录才有 `.cursor/rules`、7 个 Skills、`ORCHESTRATOR.md` 和统一脚本。

首次打开：信任工作区 → 打开 Agent Chat → 说「读取 ORCHESTRATOR.md，报告当前模块」。
Skill 未加载时执行 `Developer: Reload Window`。

### 2.2 激活工具链（每个终端会话一次）

```powershell
# Windows PowerShell
cd D:\Research\Theoretical-Econometrics-Agent
. .\scripts\setup_env.ps1
```

```bash
# macOS / Linux
cd ~/Research/Theoretical-Econometrics-Agent
source scripts/setup_env.sh
```

预期：Python / R / TeX Live 就绪；MATLAB、Octave、Stata 按本机安装情况报告。
R 包缺失时按提示运行 `Rscript scripts/install_r_packages.R`。

> 本机尚未安装 Python/R/TeX？按 [第二篇](#第二篇从服务器完整迁移到本地windows--macos--linux-原生) 完整走一遍迁移安装。

### 2.3 确认项目状态

打开 `system/metadata.md`，核对：

- `project_slug`：当前论文目录名
- `当前模块` 与模块状态表
- `engine`：M5 用 `matlab-mcp` / `matlab-local` / `octave` / `python`
- `stata_engine`：实证辅助引擎用 `stata-mcp` / `stata-local` / `r` / `none`
- `待人裁决事项` 与 `proof gap 总账`

### 2.4 初始化论文工作区（每篇新论文一次）

```bash
python scripts/init_project.py --name your-project-slug --output projects
```

生成 `projects/your-project-slug/` 标准目录树，然后把 slug 写入 `system/metadata.md` 的 `project_slug`。

### 2.5 一句话启动

对 AI 说一句话即可；它会自动读 `ORCHESTRATOR.md` → `MODULE.md` → `SKILL.md`：

| 你想做什么 | 一句话指令示例 |
|-----------|---------------|
| 从零开一篇论文 | 「跑 M1：把这个模型想法写成可识别、可估计、可证明的正式设定」 |
| 文献与贡献 | 「跑 M2：基于 library 判断这个模型相对最近文献的边际贡献」 |
| 从证明开始 | 「从 M4 开始：模型与估计量已定，请搭建假设体系和定理地图」 |
| 只补模拟 | 「从 M5 开始：按 simulation_design.yaml 先 smoke test」 |
| 只组稿 | 「从 M6 开始：把 proofs/ 和 results/tables/ 组成 LaTeX 全稿」 |
| 模拟审稿 | 「只用 M7：对这篇理论论文做五视角评审」 |

### 2.6 快速自检

```bash
python scripts/check_environment.py --strict   # 核心环境
python scripts/validate_skills.py              # 7 个 Skill 齐全
python scripts/validate_project.py             # 发行树静态完整性（见下文说明）
```

`validate_project.py` 面向可发布的干净发行树；若日常工作目录已生成 `config/local-tools.json`、
`.cursor/mcp.json`、PDF 或 LaTeX 中间文件，它会按设计失败。

## 3. 核心概念

### 3.1 卡点（Human Checkpoint）

卡点 = **必须由你拍板、AI 不得越过**的决策点：

| # | 卡点 | 模块 | 你要决定什么 |
|---|------|------|-------------|
| 1 | 模型设定批准 | M1 | 方程或矩限制、误差与依赖结构、参数空间、识别条件是否冻结 |
| 2 | 贡献定位批准 | M2 | 贡献陈述级别（强/中/弱）、是否继续 |
| 3 | 估计方案批准 | M3 | 目标函数、集中化或优化方案、约束、**SE 类型**（影响 M5 的 CP） |
| 4 | 假设体系批准 | M4 | A1–A8 等假设是否采纳 |
| 5 | 定理逐条确认 | M4 | 每条定理：Confirmed / Candidate / Needs verification |
| 6 | 模拟设计批准 | M5 | DGP、真值、N/T、重复次数、引擎 |
| 7 | 模拟结果审视 | M5 | bias/RMSE/cp95/fail_rate 是否可接受 |
| 8 | 章节草稿审阅 | M6 | 先引言+模型节，再全稿 |
| 9 | 评审意见裁决 | M7 | 哪些意见必须改、哪些回应 |
| 10 | 返修稿审定 | M7 | response 矩阵闭环后终稿 |

遇卡点时，Agent 应把模块状态改为 `blocked_on_human`，写入 `system/metadata.md` 的「待人裁决事项」，然后停下等你。

### 3.2 阶段闸门（Stage Gates）

后一模块不得把产出当最终结论，除非前面闸门已通过（详见 `ORCHESTRATOR.md` §六）：

| Gate | 收尾模块 | 核心检查 |
|------|---------|---------|
| Gate 1 模型有效性 | M1 | 维度、识别、参数空间、依赖/变换结构与目标函数兼容 |
| Gate 2 文献落地 | M2 | 引用可核对、比较维度完整、贡献不夸大 |
| Gate 3 估计可行性 | M3 | 目标函数可算、优化与约束落实、SE 有定义 |
| Gate 4 理论闭合 | M4 | 定理绑假设、随机阶明确、proof gap 列全 |
| Gate 5 模拟可复现 | M5 | DGP 一致、种子受控、表由脚本生成 |
| Gate 6 论文一致性 | M6 | 记号/假设/定理/附录同步、编译零未定义引用 |

### 3.3 模块状态机

```
not_started → in_progress → blocked_on_human → in_progress → done
```

从中间切入时可用带来源限定：`done(stub)`、`done(external)`、`done(partial)`，备注中写明缺失项。

### 3.4 记号与证明纪律（摘要）

- 每个新符号登记到 `proofs/notation_registry.md`；正文、证明、代码三处一致。
- 证明缺口标 `Proof gap`；定理状态只用四种：`Confirmed` / `Candidate` / `Needs verification` / `Not yet proved`。
- 完整诚信清单见 `system/integrity-rules.md`。

## 4. 全模块端到端流程（方式 A）

以下以“线性模型的高斯 QML”为中性案例，说明 M1–M7 的衔接方式。完整文档见
`examples/generic-qml-workflow/`（**只读**，新工作在 `projects/{slug}/`）。
该案例只展示流程，不提供模拟结果、已核验文献结论或可投稿论文。

### 4.1 准备

1. `init_project.py` 初始化 `projects/{slug}/`
2. 把核心文献 PDF **及同名 .txt** 放入 `literature/library/`
3. `metadata.md` 填 slug、运行方式 A、`engine`

当前模板默认生成空间面板断点骨架。采用本节的中性线性模型时，应在 Gate 1 前删除或替换
不适用的 \(W_N\)、断点、regime、DGP 和论文占位内容，不得仅修改项目标题。

### 4.2 M1 模型设定

> 「跑 M1：以 \(y_i=x_i'\beta+u_i\) 为基准，写明条件均值、参数空间、高斯准似然与识别条件。」

**产出**：`config/model_specification.yaml`、`proofs/notation_registry.md`、似然推导草稿。

**卡点**：你确认模型方程、误差结构、参数空间与识别条件 → **冻结**。

**常见拒跑**：直接要定理而未冻结模型 → 框架退回 M1。

### 4.3 M2 文献定位

> 「跑 M2：基于 library 建立文献矩阵；未核验原文前不要作新颖性结论。」

先建索引：

```bash
python scripts/build_rag_index.py \
  --library projects/{slug}/literature/library \
  --out projects/{slug}/literature/index
```

**产出**：`literature/literature_matrix.csv`、`literature/positioning.md`。

**卡点**：你裁决贡献陈述级别（强/中/弱）。

### 4.4 M3 QML 估计

> 「跑 M3：推导线性高斯 QML 估计量，并给出允许条件异方差的三明治标准误。」

**产出**：`estimation/qml_estimation_plan.md`。

**卡点**：你批准估计方案，**尤其 SE 类型**——它决定 M5 覆盖率（CP）怎么算。

### 4.5 M4 渐近理论

> 「跑 M4：建立一致性与渐近正态性的假设体系、定理地图和证明蓝图。」

**产出**：`proofs/assumptions.md`、`proofs/theorem_map.md`、`proofs/proof_*.md`；proof gap 进 `metadata.md` 总账。

**卡点 ×2**：先批准假设体系；每个定理草稿完成后逐条确认状态。

### 4.6 M5 Monte Carlo

> 「跑 M5：按 simulation_design.yaml 设计异方差 DGP；先做 smoke，获批后再跑 final。」

**产出**：`matlab/`（或 `octave/` / `python/`）代码、`results/raw/`、`results/tables/`。

**卡点 ×2**：开跑 final 前批准模拟设计；表格出来后审视结果（重点看 **cp95** 与 **fail_rate**）。

**节奏**：先 `R=10` smoke → 确认路径/种子/优化器 → 再 final replication。

### 4.7 M6 论文写作

> 「跑 M6：先写模型、识别和估计方法，再按已核验材料组稿；未执行结果不得写入正文。」

LaTeX 真源在 `projects/{slug}/paper/`。若文件来自当前模板，须先替换空间面板断点专用占位内容。

**卡点**：先审引言 + 模型节定调，再审全稿。

编译与检查：

```bash
cd projects/{slug}/paper
latexmk -pdf -interaction=nonstopmode main.tex
python ../../scripts/check_latex_notation.py --tex main.tex
```

### 4.8 M7 审稿与返修

> 「跑 M7：Round 1 模型与贡献评审。」

**产出**：`reviews/` 下五视角报告、`reviews/revision_log.md`、response 矩阵。

**卡点 ×2**：每轮评审后你裁决意见；response 闭环后审定终稿。

```bash
python scripts/summarize_reviews.py --reviews projects/{slug}/reviews
```

## 5. 单模块与切入示例（方式 B / C）

| # | 场景 | 一句话指令 | 需要提供 |
|---|------|-----------|---------|
| 1 | 只做模型形式化 | 「只跑 M1：把这个想法写成正式模型」 | 模型想法 |
| 2 | 贡献审计 | 「只跑 M2：判断这个设定还有没有得做」 | 模型一句话 + 文献库 |
| 3 | 审查似然推导 | 「用 M1 审查：这是我的似然推导，对不对？」 | 推导文本/LaTeX |
| 4 | 审查已有证明 | 「用 M4 审查这份一致性证明，列 proof gap」 | 证明文本 |
| 5 | 已有理论只补模拟 | 「从 M5 开始：模型与算法见附件」 | 模型 + 算法 + `simulation_design.yaml` |
| 6 | 已有材料只组稿 | 「从 M6 开始：把这些笔记和表格组成论文」 | 推导笔记 + 表格 |
| 7 | 评审外部论文 | 「只用 M7：对这篇论文做五视角评审」 | 论文全文 |
| 8 | 回应真实审稿意见 | 「用 M7：按这份审稿意见做 response 矩阵」 | 论文 + 意见 |
| 9 | 查看通用流程 | 「说明 examples/generic-qml-workflow 中 M1–M7 如何衔接」 | — |

### 5.1 从中间切入的规则

1. Agent 先读目标模块 `MODULE.md` 的 **Requires**
2. 缺失的上游产出，用 `templates/paper-project/` 补最小 stub
3. 在 `metadata.md` 标 `done(stub)` / `done(external)` 并备注边界
4. **不得**因 stub 而跳过仍适用的卡点（例如 M5 仍要你先批准模拟设计）

### 5.2 MCP 与本地直连（M5 与其它数值任务）

| 本机有 | 配置方式 | `metadata.md` 登记值 |
|--------|---------|--------------------------|
| MATLAB + 许可证 | [matlab-mcp-server](https://github.com/matlab/matlab-mcp-server) + `.cursor/mcp.json` | `matlab-mcp` |
| MATLAB + 许可证 | [`本地化部署说明.md` §4.2](本地化部署说明.md#42-模式-b本地直连新增选项) 的终端批处理 | `matlab-local` |
| 仅 Octave | `ENVIRONMENT.md` 决策树，无需 MCP | `octave` |
| 仅 Python | R/linearmodels 交叉验证或纯 Python DGP | `python` |

### M3 QML 估计

| 项 | 内容 |
|----|------|
| Requires | M1 产出 |
| Produces | `estimation/qml_estimation_plan.md` |
| 你做 | 批准算法与 **SE 方案**（Gate 3） |
| 陷阱 | 集中化丢参数相关项；约束、边界或模型专用搜索规则未写入计划 |

### M4 渐近理论

| 项 | 内容 |
|----|------|
| Requires | M1 + M3 |
| Produces | `assumptions.md`、`theorem_map.md`、`proof_*.md` |
| 你做 | 批准假设；逐条确认定理；维护 proof gap 总账 |
| 陷阱 | 收敛速率套用通用结论；假设未绑到定理 |

### M5 Monte Carlo

| 项 | 内容 |
|----|------|
| Requires | M1 + M3 + `config/simulation_design.yaml` |
| Produces | `matlab/`、`results/raw/`、`results/tables/` |
| 你做 | 批准设计；审视 cp95/fail_rate（Gate 5） |
| 陷阱 | 手工填表；不报告不收敛；DGP 与理论模型不一致 |

### M6 论文写作

| 项 | 内容 |
|----|------|
| Requires | M1–M5 或等价材料 |
| Produces | `paper/main.tex` + 附录；`main.pdf` 在本机编译生成，不纳入发行树 |
| 工具 | `latexmk`、`check_latex_notation.py` |
| 你做 | 分阶段审阅章节（Gate 6） |
| 陷阱 | 正文与 `proofs/` 记号不一致；表不是脚本输出 |

### M7 审稿返修

| 项 | 内容 |
|----|------|
| Requires | 论文全文（框架产出或外部） |
| Produces | `reviews/*.md`、`revision_log.md`、终稿检查 |
| 工具 | `summarize_reviews.py` |
| 你做 | 裁决意见；审定返修稿 |
| 陷阱 | 让 Referee 直接改正文（违反只攻击不代笔） |

## 8. 工具链日常使用

### 8.1 每次会话

1. 进入仓库根目录
2. 激活：`setup_env.ps1`（Windows）或 `setup_env.sh`（macOS/Linux）
3. `check_environment.py --strict`（可选，排查环境问题）

### 8.2 M5 引擎选择（`ENVIRONMENT.md` 决策树）

```
本机有 MATLAB？
  ├─ 是 → MCP 已连接？
  │      ├─ 是 → matlab-mcp
  │      └─ 否 → 已在 local-tools.json 登记可执行文件？
  │             ├─ 是 → matlab-local（终端 -batch）
  │             └─ 否 → 先配置路径，再选择上述模式
  └─ 否 → 有 Octave？
         ├─ 是 → octave（保持代码兼容）
         └─ 否 → python（交叉验证 / 简化 DGP）
```

在 `metadata.md` 的 `engine` 字段写明选择，避免会话间漂移。Stata 是实证辅助引擎：
MCP 登记 `stata_engine: stata-mcp`，本地直连登记 `stata_engine: stata-local`；直连步骤见
[`本地化部署说明.md`](本地化部署说明.md)。

### 8.3 R 的角色

- M5 可用 R（`spdep`/`spatialreg`/`splm`）做**估计交叉验证**
- Linux 无 root 时空间 R 包可能装不上 → 文档已说明可降级 Python
- 安装：`Rscript scripts/install_r_packages.R`

### 8.4 TeX 与文献

- 论文编译在 `paper/` 下用 `latexmk -pdf main.tex`
- 发行树只保留 LaTeX/BibTeX 源；`main.pdf`、`.bbl` 与其他中间文件均在本机再生，不纳入发布
- RAG 索引只吃 `.txt/.md/.tex/.bib/.csv`；PDF 须配**同名 .txt**（扫描件先 OCR）

### 8.5 Word 与导出

- 程序化 docx：`python-docx`（已在 requirements.txt）
- LaTeX ↔ Word：Pandoc（可选安装）；公式与交叉引用须人工核对

## 10. 攻防协议与 Referee 使用

### 10.1 最小攻防循环

```
Researcher 写 PROPOSAL
  → Referee 写 ATTACK（标 HIGH/MEDIUM/LOW）
  → Researcher 写 RESPONSE
  → Lead Author 裁决
  → Researcher 执行 → Referee 审计
```

### 10.2 决策级别

| 级别 | 覆盖 | 轮次上限 | 典型步骤 |
|------|------|---------|---------|
| 重度 | 全五视角 | 3 | 模型设定、假设体系、核心定理、模拟设计、正式审稿 |
| 中度 | 关键维度 | 2 | 集中化推导、单条引理、文献矩阵、章节草稿 |
| 轻度 | 快速扫 | 1 | 记号统一、表格格式、编译修复 |

轻量任务可在主会话自审；**HIGH 级问题必须落盘回应**。

### 10.3 何时开独立 Referee 会话

重度子步骤（M1 模型、M4 假设/核心定理、M5 设计、M7 正式审稿）建议**新开会话**加载 `agents/referee.md`，保证攻击独立性。
Referee **只产出评审报告**，修改走 M7 返修流程。

### 10.4 五视角（M7）

理论计量 / 空间计量 / 证明审计 / 模拟审计 / 表达编辑——详见 `modules/M7-referee-revision/MODULE.md`。

# 第二篇：从服务器完整迁移到本地（Windows / macOS / Linux 原生）

本篇说明如何把服务器上的整个 `Theoretical-Econometrics-Agent/` 文件夹复制到个人电脑，
并在**本机操作系统中直接运行**。不需要 WSL2、Docker、虚拟机或远程服务器。

日常研究操作见 [第一篇](#第一篇研究使用说明)；本篇仅在**首次迁到本机**或**换电脑**时阅读。

迁移的原则是：

1. **复制研究资产和框架文件**：模块、Skill、模板、项目、文献、代码、论文与状态记录全部保留。
2. **不复制运行环境**：服务器 Python 虚拟环境、R/TeX/MATLAB/Stata 安装不能跨机器复用，必须本机重装。
3. **不保留服务器绝对路径**：`/home/agent/...`、`/usr/local/...` 等路径改为本机配置。
4. **每台电脑各有一份本机配置**：`config/local-tools.json` 和 `.cursor/mcp.json` 不进入版本库。

### 一、迁移前：服务器端应复制什么

#### 1. 必须复制

复制整个 `Theoretical-Econometrics-Agent/` 目录，包括隐藏目录：

```text

├── .cursor/          # 必须保留：Rules、7 个 Skills；隐藏目录容易漏掉
├── agents/
├── config/           # 复制 example/schema；local-tools.json 如存在不要沿用
├── examples/
├── modules/
├── paper-lib/
├── projects/         # 最重要：正在进行的论文项目
├── scripts/
├── system/           # metadata 与 proof gap 总账
├── templates/
├── README.md
├── ORCHESTRATOR.md
├── ENVIRONMENT.md
├── requirements.txt
└── 使用手册.md
```

尤其检查以下研究资产已经包含：

- `projects/{slug}/literature/library/`：本地文献 PDF/TXT/BibTeX；
- `projects/{slug}/proofs/`：记号、假设、定理地图与证明草稿；

- 服务器外部的 `/home/agent/research-agent/tools/py_env`：Python venv 写入了解释器绝对路径，跨机器必坏；
- 服务器外部的 `/home/agent/research-agent/tools/R`：可执行文件与操作系统/CPU 绑定；
- `/usr/local/texlive/2026/...`：TeX Live 必须本机安装；

- `.cursor/mcp.json`：里面是服务器绝对路径；

> 个人 `projects/` 中自有论文、数据与结果不属于发行包。

### 九、MATLAB 官方 MCP：本地原生配置

MATLAB MCP 只在**拥有合法本机 MATLAB 安装与许可证**时使用。
官方服务器为 [matlab/matlab-mcp-server](https://github.com/matlab/matlab-mcp-server)。
当前官方要求 MATLAB R2021a+，并支持最近五年的 MATLAB 版本；以其最新 README 为准。
不需要交互式 MCP 时，可改用
[`本地化部署说明.md` §4.2 的 MATLAB 本地直连](本地化部署说明.md#42-模式-b本地直连新增选项)，
并在 `metadata.md` 登记 `engine: matlab-local`。

#### 1. 下载服务器

从官方 Releases 下载对应二进制：

- Windows x64：`matlab-mcp-server-windows-x64.exe`
- Linux x64：`matlab-mcp-server-linux-x64`
- macOS Apple Silicon：`matlab-mcp-server-macos-arm64`
- macOS Intel：`matlab-mcp-server-macos-x64`

macOS/Linux 下载后：

```bash
chmod +x /absolute/path/to/matlab-mcp-server
```

也可安装 Go 后从源码构建：

```bash
go install github.com/matlab/matlab-mcp-server/cmd/matlab-mcp-server@latest
```

#### 2. 配置 Cursor

复制对应模板：

```powershell
# Windows
Copy-Item .\scripts\mcp\mcp.windows.json.example .\.cursor\mcp.json
```

```bash
# macOS
cp scripts/mcp/mcp.macos.json.example .cursor/mcp.json

# Linux
cp scripts/mcp/mcp.linux.json.example .cursor/mcp.json
```

然后替换：

- `command`：MCP 二进制绝对路径；
- `--matlab-root=...`：MATLAB 根目录，**不含 `/bin`**；
- `--initial-working-folder=...`：本项目根目录绝对路径。

Windows JSON 路径使用 `\\`。保存后执行 `Developer: Reload Window`。

如使用连接现有 MATLAB session 的模式，需要按官方说明运行一次：

```bash
/absolute/path/to/matlab-mcp-server --setup-matlab
```

#### 3. 验证

在 Cursor MCP 设置中确认 `matlab` 为绿色/已连接，再让 Agent：

> 「调用 MATLAB，执行 `version`、`pwd` 和 `2+2`，只报告输出。」

然后进入一个项目的 `matlab/`，运行 smoke test。不要直接从 1000 次 final replication 开始。

常见故障：

- **MATLAB not found**：`--matlab-root` 写成了 `...\bin`，应改为版本根目录；
- **Windows 路径 JSON 解析失败**：单反斜杠未转义；
- **macOS Permission denied**：未执行 `chmod +x`，或 Gatekeeper 隔离了下载文件；
- **工作目录错误**：补 `--initial-working-folder`；
- **旧 server 名称失效**：官方 v0.11 起从 core server 更名为 `matlab-mcp-server`，重新下载并更新配置。

### 十三、常见迁移故障

#### PowerShell 无法运行 Activate.ps1

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

关闭并重开 PowerShell。不要全局设为 `Unrestricted`。

#### `python` 指向 Microsoft Store 或系统旧版本

使用 `py -0p` 查看安装，创建环境时明确 `py -3.10 -m venv .venv`。

#### `pip` 安装到了系统环境

确认提示符前有 `(.venv)`，并使用：

```bash
python -m pip --version
python -m pip install -r requirements.txt
```

#### R 包在 Windows/macOS 编译失败

优先安装 CRAN binary，不要强制 source；检查 R 版本是否过新导致二进制尚未发布。

#### `latexmk` 找不到

检查 `config/local-tools.json` 的 `texlive_bin`，重新打开终端；
Windows 通常为 `C:\texlive\2026\bin\windows`，macOS 为 `/Library/TeX/texbin`。

#### 文献 PDF 无法被 RAG 搜索

当前轻量索引器索引 `.txt/.md/.tex/.bib/.csv`。可搜索 PDF 必须先导出同名 TXT；
扫描 PDF 要先 OCR。`pypdf` 只能抽取有文字层的 PDF。

#### Cursor 看不到 Skills

确认打开根目录且 `.cursor/skills/m1-.../SKILL.md` 存在，执行：

```bash
python scripts/validate_skills.py
```

然后 `Developer: Reload Window`。

#### MCP 配置修改后没有生效

1. 检查 JSON 语法；
2. 检查 `command` 是否为绝对路径；
3. Windows 检查 `\\`；
4. 重载 Cursor；
5. 查看 Cursor MCP 日志；
6. 先在普通终端直接运行 MCP server/doctor，排除 Cursor 之外的问题。
