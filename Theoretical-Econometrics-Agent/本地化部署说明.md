# 本地化部署说明 — Stata / MATLAB 双模式接入

> 适用对象：在个人计算机（Windows / macOS / Linux 原生环境）部署本框架的使用者。
> 本文档在现有 **MCP 接入方案**（见 `ENVIRONMENT.md`、`使用手册.md` 第二篇 §九/§十）的基础上，
> 新增 **本地直连模式**：本机已安装 Stata / MATLAB 时，不经 MCP 服务器，由 Agent 直接在终端以批处理方式调用。
> 本地直连完全复用框架既有的 `config/local-tools.json` 路径体系与 `TEA_*` 环境变量，无需新增任何约定。
> 两种模式二选一或并存均可，选定后登记到 `system/metadata.md`。
>
> **验证状态**：本次发布整改仅在当前 Linux 环境完成静态校验；下列 Windows 与 macOS
> 命令和软件调用**尚未在对应真机上执行验证**。两平台使用者必须完成 §六的人工验收清单，
> 不能把文档中的示例输出视为已验收结果。

---

## 一、部署总览

### 1.1 两种接入模式

| | 模式 A：MCP 接入（现状默认） | 模式 B：本地直连（本文新增） |
|---|---|---|
| 原理 | 在 `.cursor/mcp.json` 注册 MCP 服务器，Agent 通过 MCP 工具执行 MATLAB / Stata 代码 | Agent 在终端直接调用本机可执行文件（`matlab -batch` / Stata 批处理），路径取自 `local-tools.json` 导出的 `TEA_MATLAB_ROOT` / `TEA_STATA_CLI` |
| 前置条件 | 本机已安装并授权 + 下载 MCP 二进制 / 安装 uv + 配置 `.cursor/mcp.json` | 本机已安装并授权 + `config/local-tools.json` 已登记路径（框架部署的既有步骤，见 §2.3） |
| 优点 | 交互粒度细，可执行代码片段、查看 MATLAB 工作区变量并即时返回输出 | 零额外组件；行为与手工运行脚本完全一致，Monte Carlo 长任务日志、随机种子与输出路径完全由脚本自身控制，复现路径直观 |
| 缺点 | 需维护 MCP 二进制与配置；配置变更后须重启 Cursor 或重新加载窗口方可生效 | 每次调用为完整批处理会话，无跨调用状态（不能分步查看工作区变量） |
| 适合场景 | M5 模拟设计的探索调试阶段（改参数、看中间量、跑小规模试算） | smoke test 之后的成规模 replication 正式运行、跨机器复现、不便配置 MCP 的环境 |

两种模式**不互斥**：典型用法是探索调试走 MCP、最终 1000 次 replication 走本地直连整脚本运行。同一张正式结果表仅采用一种来源，并在 `system/metadata.md` 与脚本头部注明。

### 1.2 部署路线图

```
0. 先读 Windows / macOS 差异对照            → 本文 §2.2（避免误用其他平台的命令）
1. 基础工具链（Python / R / TeX Live）      → 按《使用手册》第二篇 §三–§八完成，本文不重复
2. 登记本机路径（两种模式共用）             → 本文 §2.3：configure_local.py 生成 local-tools.json
3. Stata   ├─ 走 MCP    → 本文 §3.1（指向《使用手册》第二篇 §十）
           └─ 走本地直连 → 本文 §3.2 ★
4. MATLAB  ├─ 走 MCP    → 本文 §4.1（指向《使用手册》第二篇 §九）
           └─ 走本地直连 → 本文 §4.2 ★
5. 登记与验收                               → 本文 §5、§6
```

本机无 MATLAB / Stata 不构成阻塞：M5 模拟按 `ENVIRONMENT.md` 决策树降级为 Octave 或 Python，实证示例降级为 R（`splm` / `spatialreg`），降级须记录到 `system/metadata.md`。

## 二、基础环境与平台差异

### 2.1 前置清单（简要）

以下内容《使用手册》第二篇 §三–§八已有完整步骤，此处只列清单：

1. **Cursor** 打开**仓库根目录**（否则 `.cursor/skills|rules|mcp.json` 不生效）。
2. **Python 3.10/3.11** 虚拟环境建在仓库根 `.venv/`，安装 `requirements.txt`。
3. **R 4.4+** 与空间计量包（`spatialreg` / `splm` / `spdep` / `strucchange`），运行 `Rscript scripts/install_r_packages.R`。
4. **TeX Live / MacTeX 2026**（`latexmk`、`pdflatex`、`xelatex`）。
5. 每个终端会话先激活：Windows 执行 `. .\scripts\setup_env.ps1`（点调用），macOS/Linux 执行 `source scripts/setup_env.sh`。

### 2.2 Windows 与 macOS 差异对照（必读）

后文命令均分 Windows / macOS 两套写法，差异集中在下表。**Linux 与 macOS 属同一套 Unix 写法**（仅安装路径不同），不再单列。

| 差异点 | Windows | macOS |
|---|---|---|
| 终端 / Shell | PowerShell：环境变量 `$env:VAR`；调用带空格路径的程序须加 `&` 运算符；续行符为反引号 `` ` ``；重定向全部输出用 `*>` | 默认 zsh（bash 同理）：环境变量 `$VAR`；带空格路径加引号即可；续行符 `\`；重定向用 `> file 2>&1` |
| 激活脚本 | `. .\scripts\setup_env.ps1`（**点 + 空格**的点调用，否则环境变量不保留；首次使用可能需执行 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`） | `source scripts/setup_env.sh` |
| Stata 可执行文件位置 | 独立 `.exe`，位于安装目录下直接可见：`C:/Program Files/Stata19/StataMP-64.exe` | 位于 **`.app` 程序包内部**（Finder 中需右键「显示包内容」方可查看），批处理应使用其中的**命令行程序**（小写，如 `stata-mp`）：`/Applications/Stata/StataMP.app/Contents/MacOS/stata-mp` |
| Stata 批处理参数 | `/e do`（批处理运行，不弹出窗口与完成提示） | `-b do` |
| Stata 日志编码 | 中文 Windows 环境常为 **GBK**，直接打开可能乱码（见 §七 Q3） | UTF-8，一般无乱码问题 |
| MATLAB 根目录（`matlab_root`） | `C:/Program Files/MATLAB/R2026a`（不含 `bin`） | `/Applications/MATLAB_R2026a.app`（**`.app` 本身即根目录**，同样不含 `bin`） |
| MATLAB 可执行文件 | `{matlab_root}\bin\matlab.exe` | `{matlab_root}/bin/matlab` |
| JSON 内路径转义（`local-tools.json`、`mcp.json`） | 反斜杠必须写作 `\\`，或改用正斜杠 `/` | 原生正斜杠，无此问题 |
| 下载的 MCP 二进制（模式 A） | `matlab-mcp-server-windows-x64.exe` 下载后即可使用 | 需区分 Apple Silicon（`-macos-arm64`）与 Intel（`-macos-x64`）；下载后执行 `chmod +x`，首次运行会被 **Gatekeeper** 拦截：执行 `xattr -d com.apple.quarantine /path/to/matlab-mcp-server`，或在"系统设置 → 隐私与安全性"中放行 |
| uv 安装（模式 A，Stata） | `irm https://astral.sh/uv/install.ps1 \| iex` | `curl -LsSf https://astral.sh/uv/install.sh \| sh` |

小结：Windows 的高频问题集中在**点调用激活、JSON 反斜杠转义、`/e` 参数、GBK 编码**；macOS 的高频问题集中在 **`.app` 包内路径、命令行程序与 GUI 程序之分、Gatekeeper 放行、芯片架构选错二进制**。

### 2.3 登记本机路径（两种模式共用，必做）

框架的路径真源是 `config/local-tools.json`（已被 gitignore，不入库）。生成方式二选一：

```bash
# 自动探测（优先使用）：从 PATH 与常见安装位置探测
python scripts/configure_local.py

# 探测不到时显式指定（示例为 macOS；Windows 路径改用正斜杠或 \\）
python scripts/configure_local.py --force \
  --matlab-root "/Applications/MATLAB_R2026a.app" \
  --stata-cli   "/Applications/Stata/StataMP.app/Contents/MacOS/stata-mp"
```

登记后验证：

```bash
python scripts/check_environment.py --strict
```

输出中 `MATLAB` 与 `Stata` 两行应显示实际路径而非 `not configured`。此后每次激活环境（§2.1 第 5 条），`setup_env.ps1` / `setup_env.sh` 会自动将其导出为环境变量 `TEA_MATLAB_ROOT` 与 `TEA_STATA_CLI`——**模式 B 直接引用这两个变量，不需要任何额外配置**。

## 三、Stata 部署

Stata 在本框架中为**辅助引擎**：仅用于实证应用示例（empirical illustration）或对照 `xsmle` / `spxtregress` 已有结果。无 Stata 时降级为 R，见 `ENVIRONMENT.md` §二.5。

### 3.1 模式 A：MCP 接入（现状方案，指引）

配置方法不在本文重复：安装 uv → `uvx stata-mcp install -c cursor` → `uvx stata-mcp doctor` 验证，完整步骤见《使用手册》第二篇 §十；分平台客户端模板见 `scripts/mcp/mcp.windows.json.example` / `mcp.macos.json.example` / `mcp.linux.json.example`（模板中 `STATA_CLI` 与 `STATA_MCP__CWD` 均须替换为本机实际路径）。

### 3.2 模式 B：本地直连（新增选项）

前提：§2.3 已完成，`local-tools.json` 的 `stata_cli` 字段已登记且 `check_environment.py` 可探测到。

#### 第 1 步：确认可执行文件路径

| 平台 | 典型路径（以本机实际版本为准） |
|---|---|
| Windows | `C:/Program Files/Stata19/StataMP-64.exe`（授权版本不同则为 `StataSE-64.exe` / `StataBE-64.exe`） |
| macOS | `/Applications/Stata/StataMP.app/Contents/MacOS/stata-mp`（命令行程序，小写；SE 版为 `stata-se`，BE 版为 `stata`） |
| Linux | `/usr/local/stata19/stata-mp` |

macOS 注意：`Contents/MacOS/` 目录下同时存在图形界面程序（与 `.app` 同名，如 `StataMP`）与命令行程序（小写带连字符）。批处理模式应使用**命令行程序**，以图形界面程序运行批处理可能唤起 GUI。可在终端执行 `ls /Applications/Stata/*.app/Contents/MacOS/` 确认实际文件名。

首次安装后须手工启动一次 Stata 完成授权，再执行后续步骤。

#### 第 2 步：批处理运行 do 文件

先激活环境（§2.1 第 5 条）使 `TEA_STATA_CLI` 生效，再**从仓库根目录**运行；do 文件内的输出路径统一写入 `projects/{slug}/results/`：

```bash
# macOS / Linux —— 在仓库根执行（参数为 -b）
cd /path/to/Theoretical-Econometrics-Agent
"$TEA_STATA_CLI" -b do "projects/your-slug/xxx.do"
```

```powershell
# Windows PowerShell —— 在仓库根执行（参数为 /e，变量前须加 & 调用运算符）
Set-Location D:\Research\Theoretical-Econometrics-Agent
& $env:TEA_STATA_CLI /e do "projects/your-slug/xxx.do"
```

说明：

- **批处理参数是两平台最易混淆的差异**：Windows 使用 `/e`，macOS/Linux 使用 `-b`。
- 批处理模式会在**当前目录**生成与 do 文件同名的 `.log`；正式脚本应在开头显式声明 `log using` 将日志定向到 `projects/{slug}/results/`，仓库根残留的 `.log` 应及时删除，不得提交。
- do 文件内含盘符的路径必须加双引号并统一使用正斜杠，否则 Windows 下会被 Stata 解析为命令。

#### 第 3 步：在 Cursor 中告知 Agent 使用本地直连

本地直连不依赖 MCP 服务器状态，新会话中说明一次即可，例如：

> 「本机 Stata 走本地直连：可执行文件路径见环境变量 `TEA_STATA_CLI`（激活脚本已导出），请在终端从仓库根以批处理方式运行 do 文件，不要调用 Stata MCP 工具。」

建议同时将该说明写入 `system/metadata.md`（见 §5），跨会话接手时 Agent 可自动读取。

#### 第 4 步：验证

macOS / Linux：

```bash
# 在仓库根创建最小 do 文件并批处理运行
printf 'display c(stata_version)\ndisplay c(pwd)\n' > _smoke.do
"$TEA_STATA_CLI" -b do _smoke.do
cat _smoke.log      # 应输出版本号与仓库根路径，且无报错
rm _smoke.do _smoke.log
```

Windows PowerShell：

```powershell
# 使用 ASCII 编码写入，避免 UTF-8 BOM 干扰 Stata 解析首行
@'
display c(stata_version)
display c(pwd)
'@ | Set-Content -Encoding ASCII _smoke.do
& $env:TEA_STATA_CLI /e do _smoke.do
Get-Content _smoke.log    # 若中文乱码，用支持 GBK 编码的编辑器打开（参见 §七 Q3）
Remove-Item _smoke.do, _smoke.log
```

输出版本号与仓库根路径即视为部署成功。

### 3.3 如何选择

Stata 在本框架中调用频率低、任务单一（实证示例），**多数情况下模式 B 已足够**；仅当需要 Agent 高频交互式执行 Stata 片段时才有必要配置 MCP。

## 四、MATLAB 部署

MATLAB 是 M5 Monte Carlo 模拟的**主力引擎**（理论计量惯例）。无 MATLAB 时按降级链处理：Octave 运行同一套 `.m` 代码（避免专有工具箱函数）→ Python（numpy + scipy）等价实现，见 `ENVIRONMENT.md` §二.4。

### 4.1 模式 A：MCP 接入（现状方案，指引）

MathWorks 官方开源 [matlab/matlab-mcp-server](https://github.com/matlab/matlab-mcp-server)。完整步骤见《使用手册》第二篇 §九：下载对应平台二进制（macOS 区分 Apple Silicon 与 Intel）→ macOS/Linux 执行 `chmod +x` 并处理 Gatekeeper（见 §2.2 表）→ 复制分平台模板为 `.cursor/mcp.json` 并替换 `command`、`--matlab-root`（**不含 `bin`**）、`--initial-working-folder`（本仓库根）→ `Developer: Reload Window` 后验证。

### 4.2 模式 B：本地直连（新增选项）

前提：§2.3 已完成，`local-tools.json` 的 `matlab_root` 字段已登记。要求 MATLAB R2019a 及以上版本（`-batch` 参数自该版本引入）。

#### 第 1 步：确认根目录与可执行文件

| 平台 | `matlab_root`（登记值） | 可执行文件（由此推导） |
|---|---|---|
| Windows | `C:/Program Files/MATLAB/R2026a` | `C:/Program Files/MATLAB/R2026a/bin/matlab.exe` |
| macOS | `/Applications/MATLAB_R2026a.app` | `/Applications/MATLAB_R2026a.app/bin/matlab` |
| Linux | `/usr/local/MATLAB/R2026a` | `/usr/local/MATLAB/R2026a/bin/matlab` |

`matlab_root` 与模式 A 的 `--matlab-root` 取值一致（均不含 `bin`），两种模式共用同一条登记。

#### 第 2 步：批处理运行 .m 脚本

先激活环境使 `TEA_MATLAB_ROOT` 生效，从仓库根运行；先运行项目的 smoke test，再进入成规模 replication：

```bash
# macOS / Linux —— 运行项目 matlab/ 目录下的 smoke test
cd /path/to/Theoretical-Econometrics-Agent
"$TEA_MATLAB_ROOT/bin/matlab" -batch "cd('projects/your-slug/matlab'); run('smoke_test.m')" \
  > "projects/your-slug/results/raw/smoke_test.log" 2>&1
```

```powershell
# Windows PowerShell（& 调用运算符 + 反引号续行 + *> 重定向全部输出）
Set-Location D:\Research\Theoretical-Econometrics-Agent
& "$env:TEA_MATLAB_ROOT\bin\matlab.exe" -batch "cd('projects/your-slug/matlab'); run('smoke_test.m')" `
  *> "projects/your-slug/results/raw/smoke_test.log"
```

说明：

- **`-batch` 参数两平台完全一致**（与 Stata 不同，无 `/e` 与 `-b` 之分）；差异仅在 shell 语法（重定向与续行符，见 §2.2 表）。
- `-batch` 自动包含无桌面、无欢迎屏，脚本出错时以非零退出码结束（便于 Agent 判断成败）；**不要**混用旧式 `-nodisplay -nosplash -r "...; exit"` 写法。
- `-batch` 字符串中先 `cd` 进项目 `matlab/` 目录再 `run`，使脚本内相对路径按项目约定解析。
- `smoke_test.m` 为脚本名示例，以项目 `matlab/` 内的实际入口脚本为准。模板初始化的项目入口为
  `main_run_simulation.m`；正式运行前应为具体模型编写小规模试算配置或独立 smoke 脚本。
- 模拟脚本必须满足底线要求：记录随机种子、DGP、参数真值、样本规模、重复次数与输出路径；结果表由脚本生成，不手工输入（`ORCHESTRATOR.md` 既有规则）。

#### 第 3 步：在 Cursor 中告知 Agent

> 「本机 MATLAB 走本地直连：可执行文件为 `TEA_MATLAB_ROOT` 下的 `bin/matlab`，请用 `-batch` 从仓库根运行 .m 脚本，日志重定向至 `projects/{slug}/results/`，不要调用 MATLAB MCP 工具。」

#### 第 4 步：验证

```bash
# macOS / Linux
"$TEA_MATLAB_ROOT/bin/matlab" -batch "disp(version); disp(pwd)"
```

```powershell
# Windows PowerShell
& "$env:TEA_MATLAB_ROOT\bin\matlab.exe" -batch "disp(version); disp(pwd)"
```

能正确输出版本号与当前目录（应为仓库根）即视为部署成功。随后运行一次项目 smoke test，确认脚本级调用无误后，方可开始成规模 replication。

### 4.3 如何选择

- M5 探索调试阶段（改模拟参数、查看中间量、小规模试算）→ **模式 A**：MCP 可分步执行并查看工作区变量。
- smoke test 通过后的正式 replication（长时间批量运行）→ **模式 B**：整脚本批处理，日志、种子与输出完全由脚本控制，复现最直接。
- 希望以最低配置成本运行或不便配置 MCP → **模式 B** 即可覆盖 M5 全部需求。

## 五、部署结果登记

部署完成后登记以下三处，确保跨会话、跨机器接手时 Agent 无需重复确认环境：

1. **`config/local-tools.json`**（两种模式共用的路径真源）：`matlab_root` 与 `stata_cli` 填写本机实际路径；该文件不入库。
2. **`system/metadata.md`**：M5 主引擎写入 `engine`，枚举为 `matlab-mcp` /
   `matlab-local` / `octave` / `python`；例如本地批处理写 `engine: matlab-local`。
   Stata 辅助路线另写 `stata_engine`，枚举为 `stata-mcp` / `stata-local` / `r` /
   `none`。具体路径只留在 `config/local-tools.json`，不要写进可发布 metadata。
3. **`.cursor/mcp.json`**（仅模式 A 需要）：只保留实际启用的服务器条目；该文件已被 gitignore，**不得提交**。模式 B 不需要此文件；两种模式并存时，不要注册两个同用途的服务器。

模拟与估计脚本头部照常注明所用引擎与版本（`ENVIRONMENT.md` §三既有规则，与接入模式无关）。

### 6.1 通用验收

全部核对通过后，视为本地化部署完成：

- [ ] 基础工具链通过：`python scripts/check_environment.py --strict` 通过（退出码为 0），`python scripts/validate_skills.py` 通过；
- [ ] `config/local-tools.json` 已生成，`check_environment.py` 输出中 MATLAB / Stata 显示实际路径（未安装者除外）；

## 七、常见问题

**Q1：两种模式能否同时启用？**
可以。MCP 配置与本地直连互不干扰，且共用 `local-tools.json` 的同一条路径登记。但同一张正式结果表仅采用一种来源，并在脚本头部与 `system/metadata.md` 注明，避免复现歧义。

**Q2：`TEA_MATLAB_ROOT` / `TEA_STATA_CLI` 为空，如何排查？**
按路径解析优先级检查（`ENVIRONMENT.md` §一）：当前终端是否已执行激活脚本（Windows 须**点调用** `. .\scripts\setup_env.ps1`）；`config/local-tools.json` 是否存在且对应字段非空；必要时重新运行 `python scripts/configure_local.py --force` 并显式传入路径。

**Q3：本地直连时 Stata 日志出现乱码，如何处理？**
中文 Windows 环境下 Stata 日志通常为 GBK 编码。用支持编码切换的编辑器打开，或让 Agent 按 UTF-8 → GBK → GB18030 顺序尝试解码。

**Q4：Windows 下批处理报 `command C is unrecognized` 类错误，是什么原因？**
通常由 do 文件内含盘符的路径未加双引号导致。含盘符路径一律加双引号并使用正斜杠。

**Q5：`matlab -batch` 提示找不到脚本或函数，如何排查？**
确认从仓库根启动，且 `-batch` 字符串中已先 `cd` 进项目 `matlab/` 目录；若依赖工具箱函数，注意降级到 Octave 时专有工具箱不可用（`ENVIRONMENT.md` §二.4）。

**Q6：macOS 上 MCP 二进制无法启动（Permission denied 或"无法验证开发者"），如何处理？**
前者是未执行 `chmod +x`；后者是 Gatekeeper 拦截，执行 `xattr -d com.apple.quarantine /path/to/matlab-mcp-server` 或在"系统设置 → 隐私与安全性"中放行。另确认下载的二进制与芯片架构匹配（Apple Silicon 用 `-macos-arm64`）。

**Q7：本文档与 `ENVIRONMENT.md`、《使用手册》第二篇是什么关系？**
`ENVIRONMENT.md` 定义环境契约、路径优先级与引擎路由（以 MCP 为默认方案）；《使用手册》第二篇是服务器 → 本地的完整迁移流程（含 MCP 的逐步配置）；本文档聚焦 Stata / MATLAB 的接入模式选择，新增本地直连选项。基础环境安装以手册第二篇为准，本文不重复维护。
