# M2 — 数据接入与样本侦查

本模块支持两种模式，但共享同一个不可跳过的核心卡点：

- `audit_only`（默认）：输入已清洗、已构建的最终样本，只做最终样本侦查。
- `full_pipeline`（扩展）：从原始数据开始，先按 Skill 步骤 1–5 完成可复现的清洗与构建，再做样本侦查。

无论哪种模式，**缺失值全景诊断必须先于缩尾、插补和删除**。

---

## Requires（前置输入）

- `m2_mode`：`audit_only` 或 `full_pipeline`
- `audit_only`：已清洗、已构建的最终分析样本路径（`.dta` / `.parquet` / `.csv`）
- `full_pipeline`：原始数据清单、来源说明、合并键和预期样本范围
- 变量清单 / codebook（哪些是被解释变量、核心解释变量、控制变量）
- 研究窗口与样本范围说明（来自 M1 的 `paper-brief.md`，或你直接提供）

## Produces（产出）

- `paper/{project-slug}/review/sample-audit-report.md` — 缺失全景 + 分组对比 + 缺失模式诊断（只呈现事实，不含处理建议）
- 缺失值处理决策记录（人裁决后）→ 写入 codebook 的「缺失值处理」节
- `data/final/codebook.md` — 变量构造、样本筛选、缺失处理与缩尾决定
- 处理前/后的样本（版本化另存，不覆盖上一个版本）
- `data/final/schema.yaml` + Schema 验证日志

## 卡点（人裁决）

**缺失值处理决策**：智能体只诊断、只汇报，**禁止在人回复前执行任何缩尾/插值/删除**。

---

## 为什么样本侦查先于缩尾

缩尾会改变极端值分布，掩盖缺失模式。先诊断缺失、定处理策略，再缩尾。
没有「默认正确」的缺失处理方式——同一缺失率，原因不同，处理完全不同：

- 研发支出缺失 → 真没研发（填 0）还是未披露（不能填 0）？
- 分析师覆盖缺失 → 真没人覆盖（填 0）还是数据源不完整（补源）？
- 收益率缺失 → 停牌（删除）还是数据遗漏（补源）？

智能体的职责是把缺失全景呈现给人，由人用领域知识判断。

---

## 执行流程

### Step 1：缺失值全景扫描

对样本中所有变量输出缺失率报告（从高到低）：

```python
missing = df.isna().mean().sort_values(ascending=False)
print(missing[missing > 0])
```

```stata
mdesc
```

汇报：每个有缺失变量的缺失率；核心变量缺失标红；缺失率 > 10% 标黄。

### Step 2：缺失原因诊断（关键）

**2.1 分组对比**：对每个缺失率 > 0 的变量，分「有值组」vs「缺失组」，对比核心特征均值差异 + t 检验。

```python
df['group'] = df['target_var'].isna().map({True: 'missing', False: 'observed'})
print(df.groupby('group')[['size', 'bm', 'ret', 'lev']].mean())
```

**2.2 缺失模式判断框架**：

| 模式 | 特征 | 典型场景 |
|------|------|----------|
| MCAR（完全随机） | 两组在所有可观测变量上无显著差异 | 录入遗漏、随机抽样 |
| MAR（随机缺失） | 两组在某些可观测变量上有显著差异 | 小公司更可能不披露研发 |
| MNAR（非随机缺失） | 缺失与未观测因素有关 | 业绩差的公司更可能不披露 |

> 分组对比只能提供“反对 MCAR”的证据；未发现显著差异不能证明 MCAR。MAR 与 MNAR 无法仅靠已观测数据区分，必须结合数据生成机制和领域知识判断。

**2.3 缺失相关性**：检查缺失变量之间是否系统性关联（缺失矩阵相关系数 > 0.5 提示共享缺失原因）。

### Step 3：向人汇报，等待决策（卡点）

汇总 Step 1-2，提交结构化汇报（见 `templates/sample-audit-report-template.md`）：

```markdown
## 样本侦查汇报 — [数据集名称]
### 缺失全景
| 变量 | 缺失率 | 缺失观测数 | 分组对比结果 | 初步判断 |
|------|--------|-----------|-------------|----------|
### 缺失模式
- [哪些变量缺失高度相关]
### 待人决策
请逐变量给出处理方案（删除 / 替换为0 / 均值填充 / 模型插补 / 不处理）及理由。
```

**禁止在人回复前执行任何处理。**

提交报告后立即把 `system/metadata.md` 中 M2 状态改为 `blocked_on_human`。Lead Author 记录逐变量决定后，再改回 `in_progress` 执行 Step 4。

### Step 4：人决策后执行并记录

按人批准的决策逐变量执行，记录：删除→记 N-change；替换为0→记理由；填充→记方法参数；不处理→记原因。
全部写入 codebook「缺失值处理」节。处理后样本另存新文件。

---

## 与下游的关系

```
audit_only:     外部最终样本 → 【M2 样本侦查】 → 人裁决 → 缺失处理/缩尾 → 冻结样本
full_pipeline:  raw → clean → build → 【M2 样本侦查】 → 人裁决 → 缺失处理/缩尾 → 冻结样本
                                                                          ↓
                                                               M3 描述统计 + 估计
```

缩尾必须在样本侦查完成、人决策之后，在干净样本上执行。

## 独立运行说明

M2 完全可独立运行：只要你给一个数据文件 + 变量角色说明，就能跑缺失诊断。
若无 M1 的 `paper-brief.md`，请直接告知被解释变量/核心解释变量是哪些，用于标红核心变量。

模板见 `templates/sample-audit-report-template.md`。
