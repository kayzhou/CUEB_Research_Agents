## 决策一：反对党不只存在于提案阶段

### 核心理念

"执政党（Researcher）vs 反对党（Referee）"的自迭代模式不应仅限审稿阶段，而应贯穿**所有阶段的所有关键子步骤**。

就像一个高水平研究生（Researcher）在和导师开会前，先和同学（Referee）过一遍——同学挑刺，研究生改，反复几轮，拿给导师的已经是打磨过的版本。

### 工程理由

1. **错误发现成本递增**：数据清洗阶段的错误到估计阶段发现，回溯成本远高于当场发现
2. **单一Agent确认偏误**：自己写的东西天然有路径依赖，外部攻击强制重新审视
3. **自升级诊断信号更丰富**：能学到"清洗脚本总是忘了去重"而非仅"提案写得不好"
4. **人看到的不是半成品**：经攻防后的输出，人只需终审裁判

### 分级攻击强度

不是每个步骤都需要3轮攻防。按决策不可逆程度分级：

| 级别 | 决策特征 | 攻击强度 | 适用步骤 |
|------|----------|----------|----------|
| **重度** | 难回退、决定下游走向 | 2-3轮，全部攻击维度 | 样本筛选、识别策略、主回归规格、证据链 |
| **中度** | 可回退但重做成本高 | 1-2轮，聚焦攻击 | 变量构造、诊断解读、章节草稿 |
| **轻度** | 易修正的格式问题 | 0-1轮，快速扫 | 表格格式、文件命名、编译修复 |

### 各阶段反对党部署

#### 阶段1：数据

```
数据清洗 [中度]
  R: 写清洗脚本 → F: 攻击(变量构造、合并键、缺失标记) → R: 回应 → 执行

样本构建 [重度]
  R: PROPOSAL → F: ATTACK → R: RESPONSE → F: ATTACK-R2 → R: RESPONSE-R2
  → 提交给人(样本侦查卡点)

缩尾+codebook [轻度]
  R: 执行 → 快速自检 → 输出
```

#### 阶段2：估计

```
描述统计 [轻度]
  R: PROPOSAL → F: 快速扫 → 执行

主估计 [重度]
  R: PROPOSAL → F: ATTACK(识别威胁/替代解释/遗漏变量/标准误)
  → R: RESPONSE → F: ATTACK-R2 → R: RESPONSE-R2 → F: FINAL-VERDICT
  → 提交给人(估计计划批准卡点)

诊断检验 [中度]
  R: 诊断结果 → F: 攻击(平行趋势真平？F值够？安慰剂有效？) → R: 回应

表图输出 [轻度]
  R: 表格草稿 → F: 快速扫(星号/SE标注/注释) → 修正
```

#### 阶段3：写作

```
证据链 [重度]
  R: 草案 → F: 攻击(逻辑跳跃/循环论证/证据不支撑)
  → R: 修订 → 提交给人(证据链批准卡点)

章节起草 [中度，每节]
  R: 草稿 → F: 攻击(overclaim/引用不支撑/因果语言无识别) → R: 修改

编译检查 [轻度]
  R: 编译 → F: 扫(overfull hbox/表格断裂) → 修正
```

#### 阶段R：审查

```
双Referee设计 [重度]
  Referee-A: 7R逻辑审查
  Referee-B: 7Q质量评估
  A⟷B交叉验证 → joint-review.md(一致意见+分歧点)
  → 提交给人: 一致采纳/分歧裁决
```

## 决策二：模板→项目迁移策略

### 问题

当前仓库是模板（_template是预留槽位），V3.0升级后，已在运行的V2.2本地项目怎么办？

### 方案：模板干净 + 升级叠加

#### 模板仓库结构

```
模板仓库（本仓库）
  ├── agents/           ← 通用角色文件（不进项目特定内容）
  ├── system/           ← 注册表schema（空模板）
  ├── guides/           ← 方法指南
  ├── templates/        ← 代码/章节模板
  ├── code/             ← 通用工具和配置
  └── paper/            ← 空槽位
```

#### 升级操作指南 UPGRADE-V3.md

每个本地项目执行此checklist即可升级：

```markdown
## 前置检查
- [ ] 确认当前版本：VERSION = 2.2
- [ ] Git状态干净
- [ ] 备份：cp CLAUDE.md CLAUDE.v2.md

## 新增（从模板仓库复制，不影响项目文件）
- [ ] agents/          → 复制到项目根
- [ ] system/          → 复制到项目根  
- [ ] guides/hook-system.md, meta-improvement.md → 复制
- [ ] code/utils/validate_claims.py, experiment_summary.py → 复制

## 替换
- [ ] CLAUDE.md       → V3.0模板版（旧版保留）
- [ ] VERSION          → "执本忘筌 V3.0"
- [ ] guides/agent-collaboration.md → V3.0版

## 项目初始化
- [ ] system/metadata.md → 填入当前项目信息和阶段
- [ ] system/claim-registry.json → 空schema
- [ ] system/experiments.schema.json → 字段约束；system/experiments.jsonl → 首次 M3 实验时运行时创建

## 验证
- [ ] python code/utils/version_check.py 通过
- [ ] 启动CC确认读到V3.0 CLAUDE.md
- [ ] 启动Researcher确认路由到agents/researcher-role.md

## 绝对不碰
- paper/{project-slug}/ （论文内容）
- data/ result/ （数据和结果）
- code/clean/ build/ analysis/ output/ （项目脚本）
- code/config/ （项目配置）
```

### 设计原则

- **纯叠加**：只加新文件，只换编排器入口
- **零触碰项目内容**：paper/data/result/code 完全不动
- **首次使用从当前阶段继续**：已完成阶段不重做
- **模板永远干净**：不承载项目特定内容

## 决策三：Researcher角色文件中嵌入分级自迭代逻辑

### Mode Selector 新增检查

```
Part 0: Mode Selector

Check D: 当前子步骤的决策级别？
  - 重度(2-3轮) → 启动Referee → 写PROPOSAL → 等ATTACK → 逐轮回应
  - 中度(1-2轮) → 启动Referee → 写快速PROPOSAL → 等快速ATTACK → 回应
  - 轻度(0-1轮) → 自检 → 直接执行
```

### 攻防轮次上限

```
轮次控制:
  Round 1: Researcher → PROPOSAL / 子步骤产出
           Referee   → ATTACK (所有问题，标优先级: HIGH/MEDIUM/LOW)
  
  Round 2: Researcher → RESPONSE (逐条: 改 / 辩 / 接受但标局限)
           Referee   → ATTACK-R2 (仅追踪未解决HIGH + 新发现)
  
  Round 3 (仅重度): 
           Researcher → RESPONSE-R2
           Referee   → FINAL-VERDICT (仅HIGH优先级遗留)
  
  强制收敛: 3轮后无论是否还有争议，提交给人
```
