## 1. 框架是什么

本框架把一篇实证论文从选题到投稿返修的全过程，拆成 **5 个可独立运行的模块**，由 **3 个角色**协作完成：

### 1.1 三角色

| 角色 | 由谁承担 | 职责 | 不可做 |
|------|---------|------|--------|
| **Lead Author** | 你（人类） | 研究主题与主要设计的最终决定权；全部卡点裁决 | — |
| **Researcher** | AI（协议见 `agents/researcher.md`） | 执行计划、拓展思考、回应攻击 | 改研究主题/范式、自动处理缺失值、未批准跑主估计、手工改结果 |
| **Referee** | AI（协议见 `agents/referee.md`） | 攻击一切产出、找漏洞、模拟专家评审 | 写正面内容、代笔修改、空泛批评 |

设计内核是「**反对党无处不在**」：每个重要产出在被采纳前，都要经过 Referee 的对抗性攻击和你的裁决。这不是流程负担，而是把审稿人的攻击提前到投稿之前。

### 1.2 五模块

```
M1 选题立项与文献调研 ──→ M2 数据接入与样本侦查 ──→ M3 模型与实证 ──→ M4 论文撰写 ──→ M5 审稿与返修
   卡点：范式批准          卡点：缺失值      卡点：估计计划、    卡点：证据链、    卡点：意见裁决、
        贡献审计结论            处理决策          典型事实、结果        章节审阅          返修稿审定
```

每个模块由两层文档定义，**编号一一对应**：

- `modules/MX-*/MODULE.md` = **思维框架**：这个模块在做什么、立场是什么、卡点在哪、产出契约（Requires/Produces）。
- `.cursor/skills/mX-*/SKILL.md` = **执行框架**：具体怎么做、先读什么文件、边界在哪、常见陷阱；该路径可被 Cursor 自动发现。

### 1.3 两个支撑系统

- **知识库 `paper-lib/`**：本机可同步《管理世界》2022–2026 PDF（当前索引 664 条）。PDF 不随 Git 分发，必须先通过检查器确认本机文件齐全。
- **工具链（`ENVIRONMENT.md`）**：Python 3.10（资产定价/图形/Word 导出）、R 4.4.1（无 Stata 时的因果推断引擎）、TeX Live 2026（论文编译）、Stata/MATLAB 经 MCP 接入。

## 2. 快速开始（10 分钟跑通）

### 2.1 激活环境

macOS/Linux 进入仓库根目录，每次开始工作前执行：

```bash
source scripts/setup_env.sh
```

Windows PowerShell 必须点调用，使环境变量保留在当前会话：

```powershell
. .\scripts\setup_env.ps1
```

首次迁移到新机器时，先在项目根创建 `.venv`、安装 `requirements.txt`，再运行
`python scripts/configure_local.py` 生成 `config/local-tools.json`。两个激活脚本都会显示仓库、Python/R/TeX 版本、核心依赖以及可选 Stata/MATLAB 路径；`setup_env.sh` 仍保留既有 Linux 服务器 `tools/` 布局作为兼容回退。不要复制其它系统的虚拟环境或可执行文件。

Python 依赖失败时运行：

```bash
pip install -r requirements.txt
```

R 分支提示计量包缺失时运行 `Rscript scripts/install_r_packages.R`。这不会自动配置 Stata/MATLAB 授权或 MCP。

### 2.2 确认项目状态

打开 `system/metadata.md`，至少核对 `project`、`current_module`、`paradigm`、`engine`；进入 M2 还要核对 `m2_mode`。模块状态表告诉你哪些产出已就绪、当前卡在哪个人工决策上。

### 2.3 一句话启动

对 AI 助手说一句话即可启动对应流程（AI 会自动读 `ORCHESTRATOR.md` → `MODULE.md` → `SKILL.md` 装载上下文）：

| 你想做什么 | 一句话指令示例 |
|-----------|---------------|
| 从零开一篇论文 | 「跑 M1：我想研究绿色信贷政策对企业投资的影响，目标期刊《管理世界》」 |
| 最终数据到了做缺失诊断 | 「跑 M2，m2_mode=audit_only：数据在 data/final/panel.parquet，被解释变量 inv，核心解释变量 gc_policy」 |
| 从原始数据开始 | 「跑 M2，m2_mode=full_pipeline：原始文件清单如下……先给清洗计划，不要直接处理缺失」 |
| 直接做实证 | 「从 M3 开始：数据已就绪，识别策略是 DID，处理组是 2018 年后纳入试点的企业」 |
| 只写/改论文 | 「用 M4：把 sections_cn/04-results.md 转成英文投稿稿」 |
| 给论文挑毛病 | 「只用 M5：对这篇论文做模拟专家评审」（附上论文全文） |

### 2.4 验证知识库可用

```bash
python code/utils/check_paperlib.py
python code/utils/paperlib_index.py --search 双重差分
```

第一条返回 `[OK]` 才表示索引中的 PDF 均可读；只看到检索命中不代表 PDF 已同步。若返回 `[BLOCKED]`，可以继续不依赖原文的任务，但不得声称已经核对文献结论。

## 3. 核心概念

### 3.1 卡点（Human Checkpoint）

卡点 = **必须由你拍板、AI 不得越过**的决策点。全框架共 7 类：

| # | 卡点 | 所在模块 | 你要决定什么 |
|---|------|---------|-------------|
| 1 | 范式决策 | M1 | 因果推断还是资产定价？用什么引擎？ |
| 2 | 贡献审计结论 | M1 | 接受贡献评级吗？评级低的维度是否继续？ |
| 3 | 缺失值处理决策 | M2 | 每个缺失变量：删除/填 0/插补/不处理，及理由 |
| 4 | 估计计划批准 | M3 | 输出清单（哪些表图、什么规格）是否批准 |
| 5 | 典型事实 + 实证结果审视 | M3 | 哪些事实进正文；结果是否可信、可进写作 |
| 6 | 证据链批准 + 章节审阅 | M4 | 论文逻辑骨架是否成立；每章草稿过不过 |
| 7 | 评审意见裁决 + 返修稿审定 | M5 | 每条意见：必改/辩驳/标局限；终稿是否定稿 |

AI 走到卡点会**停下来等你**。你回复决策后流程继续。

### 3.2 输入/输出契约（Requires / Produces）

每个模块只通过**文件**与上下游交接，不依赖隐藏状态：

```
M1  Requires: 研究想法（一句话即可）/ 目标期刊（可选）
    Produces: paper/{slug}/paper-screen.md, paper-brief.md,
              review/contribution-audit-v1.md

M2  Requires: m2_mode + 最终样本（audit_only）或 raw 清单（full_pipeline）+ 变量清单
    Produces: review/sample-audit-report.md, 冻结样本, codebook.md, schema.yaml

M3  Requires: paper-brief.md + 干净样本 + codebook
    Produces: analysis/output 脚本, results/ 表图, system/experiments.jsonl,
              stylized-facts.md, empirical-output-checklist.md

M4  Requires: results/ 实证结果 + evidence-chain + 期刊风格参考（默认 paper-lib）
    Produces: 中文讨论稿(sections_cn/) + 英文投稿稿(sections/) + 表图 note

M5  Requires: 论文全文（本框架产出或外部论文均可）
    Produces: review/ 下的内部审查、模拟评审、response letter、changelog + 最终稿
```

**从中间切入的规则**：上游产出缺失时，用对应模板补一个最小可用版本（stub），并在 `system/metadata.md` 把上游模块标为 `done(stub)` 或 `done(external)`，注明输入来源。

### 3.3 三种运行方式

- **方式 A（端到端）**：M1 → M5 顺序全跑。适合从零开始的新论文。
- **方式 B（从某步切入）**：前置条件你直接提供，从任意模块开始。适合"数据/实证已在外部完成"。
- **方式 C（单模块独立）**：只跑一个模块。典型场景：用 M5 评审一篇外部论文、用 M4 润色一段英文。

### 3.4 论文工作区与项目命名

`paper/{project-slug}/` 是一篇具体论文的主工作区，承载该研究的全部非数据成果：

- M1：`paper-screen.md`、`paper-brief.md`、贡献审计；
- M3：典型事实、实证输出清单；
- M4：证据链、章节简报、中英文稿；
- M5：逻辑审查、质量评估、模拟评审、response letter；
- 跨模块：Researcher/Referee 的攻防记录。

`{project-slug}` 必须使用能表达研究主题的小写英文 kebab-case，不使用 `paper01`、`paper02` 等无语义编号。当前项目为：

```
a-share-multifactor-pricing
```

同一个 slug 必须同步用于以下目录和状态字段：

```
paper/a-share-multifactor-pricing/
code/analysis/a-share-multifactor-pricing/
code/output/a-share-multifactor-pricing/
results/tables/a-share-multifactor-pricing/
results/figures/a-share-multifactor-pricing/
system/metadata.md → project: a-share-multifactor-pricing
```

新项目先在 M1 给出简短、稳定的 slug，例如 `green-credit-firm-investment`。初始化时：

1. 创建 `paper/{slug}/review`、`discussions`、`section-briefs`、`sections_cn`、`sections`；
2. 创建 `code/analysis/{slug}`、`code/output/{slug}`；
3. 把 `system/metadata.md` 的 `project` 改为该 slug，并在当前 shell 设置 `export PROJECT_SLUG={slug}`；
4. 从模板生成 M1 文件，不复制旧项目中的研究结论；
5. 进入 M2 后冻结 slug。改名必须同步代码、结果、论文路径和 registry 中的证据链接。

### 3.5 不可违反规则（全文见 `ORCHESTRATOR.md`）

九条规则均生效：

1. 原始数据只读；结果只由脚本生成，不手工改。
2. 论文正文数字来自结果文件（`\input{}` 引用），不手工输入。
3. 样本侦查只诊断不处理——缺失值处理必须等你决策。
4. 包优先——有 reghdfe/csdid/fixest 就不许手搓估计。
5. 审稿只攻击不代笔——Referee 产出意见，修改走返修流程。
6. 角色不越界——Researcher 不代替人裁决，Referee 不改项目产出。
7. paper-lib 只读；结论、系数和样本期必须回 PDF 原文核对。
8. 所有卡点不可跳过；到达卡点先把模块状态改为 `blocked_on_human`。
9. 除英文投稿正文外，全程中文沟通。

## 4. 全模块端到端流程（方式 A）

以一个假想项目贯穿演示：**「绿色信贷政策对重污染企业投资的影响」，目标期刊《管理世界》**。

这是用于讲解因果推断分支的示例，不是仓库当前项目。当前 `a-share-multifactor-pricing` 走资产定价 + Python，参见示例 10；不要把下述 DID 设定写回当前项目文件。

### 阶段 0：准备

```bash
source scripts/setup_env.sh          # 激活工具链
cat system/metadata.md               # 确认从空白状态开始
```

对 AI 说：

> 「跑 M1：我想研究绿色信贷政策（2012 年《绿色信贷指引》）对重污染企业投资的影响，目标期刊《管理世界》。」

---

### M1 选题立项与文献调研

**AI 依次执行**（详见 `.cursor/skills/m1-project-init/SKILL.md`）：

1. **检索知识库**：`paperlib_index.py --search 绿色信贷`、`--search 绿色金融 投资` 等多组关键词，确认《管理世界》近五年是否已有直接相关研究。
2. **论文筛查** → 产出 `paper/{project-slug}/paper-screen.md`：研究问题一句话、对标期刊、最接近文献 3-5 篇、推进判断、数据可行性初判。
3. **范式决策** → 判定为因果推断（政策冲击 → DID），引擎按 `ENVIRONMENT.md` 决策树选 Stata（有授权）或 R。
   - **【卡点 1】你裁决**：批准范式与引擎。回复示例：「批准，因果推断 + R 引擎」。
4. **论文简报** → 产出 `paper-brief.md`：可检验假设、识别逻辑（DID，处理组=重污染行业，政策时点 2012）、数据来源预期（CSMAR + 环保名录）、预期贡献、替代解释预判。
5. **文献调研 + 贡献审计** → 分层阅读（paper-lib 命中论文优先深读）、构建比对矩阵、过严苛五问 → 产出 `paper/{project-slug}/review/contribution-audit-v1.md`，给出数据/识别/机制/市场/整体五个评级。
   - **【卡点 2】你裁决**：接受评级结论。注意：评级「中/低」的维度，之后引言不得用强声称。
6. **回写状态**：`system/metadata.md` 标 M1 done，`milestones.md` 打勾。

**你在这个阶段做什么**：提供研究想法；裁决范式；读贡献审计报告并决定是否推进（这是止损的最佳时机——审计发现想法已被做过时，成本还接近零）。

---

### M2 数据接入与样本侦查

先选模式并写入 metadata：`audit_only` 直接审计最终样本；`full_pipeline` 从 raw 清单出发，按步骤 1–5 形成可重跑的 clean/build 脚本后再审计。raw 文件始终只读。

**启动**：把最终样本放入 `data/final/`（`.parquet`/`.dta`/`.csv` 均可），对 AI 说：

> 「跑 M2，m2_mode=audit_only：样本在 data/final/panel_annual.parquet。被解释变量 inv（投资率），核心解释变量 treat×post，控制变量 size、lev、roa、cash、age。」

**AI 依次执行**（详见 `modules/M2-sample-audit/MODULE.md`）：

1. **缺失值全景扫描**：逐变量缺失率（核心变量标红、>10% 标黄）。
2. **缺失原因诊断**：有值组 vs 缺失组的特征均值差异 + t 检验；检查缺失变量间相关性。显著差异可反对 MCAR，未显著不能证明 MCAR；MAR/MNAR 不能只靠已观测数据区分。
3. **结构化汇报**到 `paper/{slug}/review/sample-audit-report.md`——只呈现事实，**不给处理建议**；同时把 M2 标为 `blocked_on_human`。
   - **【卡点 3】你裁决**：逐变量给出处理方案及理由。回复示例：
     > 「roa 缺失 3.2% 判 MCAR，直接删除观测；rd（研发）缺失 41% 是未披露，不能填 0，本文不用该变量；cash 缺失集中在 2008 年前，样本期改为 2008-2023。」
4. **执行决策 + 记录**：收到逐变量决定后改回 `in_progress`，执行缺失处理和经批准的缩尾；N-change 逐步记录；另存样本；更新 codebook 与 `schema.yaml`。
5. **验证与冻结**：运行 `python code/utils/validate_schema.py data/final/panel_annual_v2.parquet`。通过后在 metadata 记录冻结文件与校验日志，M2 才能标 `done`。

**为什么这个卡点最严格**：同样是缺失，「真没有」和「没披露」的正确处理完全相反，只有你有领域知识判断。AI 擅自缩尾/插值是本框架最高级别违规。

---

### M3 模型与实证

**启动**：

> 「进入 M3。基准规格：inv = β·treat×post + 控制变量 + 企业 FE + 年份 FE，聚类到企业。」

**AI 依次执行**（详见 `.cursor/skills/m3-estimation/SKILL.md`）：

1. **步骤 0 输出清单 + 风险自检**：一次性列全所有估计/表/图（对应脚本、用途、目标位置）；以贡献审计为输入写 `paper/{slug}/estimation-risk-memo.md`。
   - **【卡点 4】你裁决**：批准估计计划。
2. **步骤 1 描述统计与典型事实**（先于任何回归）：单变量分布、截面模式、时序趋势、相关结构 → 记入 `stylized-facts.md`。
   - **【卡点 5a】你审视**：哪些事实进正文；典型事实是否提示改规格（如明显的行业异质性 → 加行业×年份 FE）。
3. **步骤 2 主估计**：
   - 分析脚本放 `code/analysis/{project-slug}/`；Stata 加载 `config.do`，Python 使用 `from code.config import PATHS`；
   - 有 Stata：经 MCP `run_stata` 执行 `reghdfe`；无 Stata：R `fixest::feols`；
   - 交叠 DID 用 `csdid`（Stata）或 `did`（R），不用朴素 TWFE。
4. **步骤 3 诊断检验**：平行趋势（事件研究图）、安慰剂检验、交叠处理偏误诊断；逐项记录统计量与判读。
5. **步骤 4 稳健性**：按 attack-memo 中的威胁逐项覆盖（换样本期/变量定义/FE/聚类层级）；记录规格波动带（通过诊断规格的系数 SD × 1.5）。
6. **步骤 5 图表输出**：`code/output/{slug}/` 的独立脚本读取机器可读估计结果，生成 PDF/PNG 与 `.tex` 到项目结果目录。禁止 GUI 手工保存。
7. **步骤 6 估计后验证 + 记录**：断言式安检；每次运行按 `system/experiments.schema.json` 追加到 `system/experiments.jsonl`，包括 KEEP/FRAGILE/DISCARD/FAILED；运行汇总工具并回写 checklist。干净克隆只预置 schema，JSONL 由首次 M3 实验以追加模式创建，不需要提前放空文件。
   - **【卡点 5b】你审视**：实证结果全景。确认后进 M4。

**建议插入攻防**：主回归属重度子步骤——让 Researcher 写 PROPOSAL，开独立会话让 Referee 攻击（识别威胁/替代解释/数据限制/方法弱点/拓展攻击五维度），你裁决后再正式跑（详见第 10 章）。

### M4 论文撰写

**启动**：

> 「进入 M4，先做证据链。」

**AI 依次执行**（详见 `.cursor/skills/m4-paper-writing/SKILL.md`）：

1. **步骤 0 证据链统筹**（动笔前）：清点所有表图各证明了什么 → 按「想知道什么→怎么知道→发现什么→替代解释→为什么是这个机制」排成证据链 → 映射到章节结构 → 写 `evidence-chain.md`。
   - **【卡点 6a】你裁决**：批准证据链与章节结构。
2. **写前装载**：先通过 `check_paperlib.py`，再检索 2-3 篇最接近范文并回 PDF 阅读。英文风格缓存可能为空；需要时先用 `fetch_style_pdf.py` 获取开放 PDF，无法获取时不得假称已对齐该范文。
3. **逐章起草**：每章先更新 section-brief → 先写 `sections_cn/` 中文讨论稿 → 再同步 `sections/` 英文投稿稿。段落遵循四拍结构（判断→数字→经济显著→对比）。
   - **【卡点 6b】你审阅**：每章中/英稿。
4. **贡献审计闭环**：引言贡献段逐条可溯源到比对矩阵；引用 paper-lib 文献时给出**具体结论与系数量级**并回 PDF 原文核对。
5. **表图 note**：自明标准（样本、变量、估计方法、SE/聚类、显著性规则），中英双版。
6. **编译与导出**：只有项目已有主 `.tex` 文件时才运行 `xelatex <中文主文件>` / `pdflatex <英文主文件>`；当前模板不会自动生成主文件。Word 交换稿放 `paper/exports/`，批注人工同步回 tex。

**关键纪律**：正文所有数字来自 `results/` 结果文件；`[TODO]/[CHECK]` 标注投稿前必须清零。

### M5 审稿与返修

**启动**：

> 「进入 M5，先做内部审查，然后模拟专家评审。」

**五个阶段**（详见 `modules/M5-review/MODULE.md`）：

1. **5.1 内部审查**（两个独立会话，互不共享上下文）：
   - 7R 逻辑审查 → `paper/{slug}/review/logic-review-v1.md`
   - 7Q 质量评估 → `paper/{slug}/review/quality-assessment-v1.md`
2. **5.2 模拟专家评审**：3 位审稿人 persona 独立评审 + 编辑信 → `paper/{slug}/review/simulated-peer-review.md`。
3. **5.3 真实意见接入**（可选）：把导师批注/真实审稿意见粘贴给 AI，逐条结构化录入 `real-expert-intake.md`。**真实意见优先级高于模拟意见**。
4. **5.4 意见合并与 triage**：全部意见去重、按 HIGH/MEDIUM/LOW 排序、判断每条触及哪一层（数据/分析/证据链/写作）。
   - **【卡点 7a】你裁决**：逐条定处置——必改 / 辩驳 / 标局限。
5. **5.5 返修执行**：按你批准的切片修改（触及数据回 M2、方法回 M3、纯写作走 M4），写 `review/response-letter.md` 和 `review/changelog.md`。
   - **【卡点 7b】你审定**：终稿 + response letter，定稿。

**审查与修改分会话**：同一个会话不可既当 Referee 又动手改正文，否则审查独立性失效。

## 5. 单模块流程示例（方式 B / C）

### 示例 1：只用 M1 做贡献审计（想法验证）

**场景**：你有个想法，想在投入数据前确认它没被做过。

> 「只跑 M1 的文献调研 + 贡献审计：想法是"分析师实地调研降低股价崩盘风险"，先查 paper-lib 再查外部，给我比对矩阵和严苛五问结论。」

产出：`paper/{slug}/review/contribution-audit-v1.md`。AI 会在 `system/metadata.md` 标 M1 为 `done(partial)` 并说明未完成项。

### 示例 2：只用 M2 诊断一份外部数据

**场景**：合作者发来一份面板数据，你想知道质量如何。

> 「只跑 M2，m2_mode=audit_only：数据是 ~/downloads/merged_panel.dta。被解释变量 tobinq，核心解释变量 esg_score。只要缺失诊断报告，不做任何处理。」

产出：`paper/{slug}/review/sample-audit-report.md`。可不依赖 M1 的 paper-brief，但必须提供变量角色、样本范围并在 metadata 把 M1 标为 `done(external)` 或 `done(stub)`。

### 示例 3：从 M3 切入（数据和设计都已就绪）

**场景**：数据清洗和缺失处理都在外部做完了，直接做实证。

> 「从 M3 开始：样本 data/final/rd_sample.parquet（codebook 我一并放在 data/final/）。识别策略是 RD，driving variable 是评分 score，cutoff = 60。上游 M1/M2 标 done(external)。」

AI 会：补 stub 记录 → 出输出清单等你批准 → 描述统计 → `rdrobust` 主估计（Stata 或 R）→ 密度检验/带宽敏感性/协变量连续性 → 出表图。
**注意**：即使从 M3 切入，估计计划批准和结果审视两个卡点仍然生效。

### 示例 4：只用 M4 做中转英

**场景**：中文初稿已有，要转成英文投稿稿。

> 「用 M4 的中转英：把 paper/{slug}/sections_cn/05-mechanism.md 转成英文。先确认指定 JFE PDF 实际存在并读取；不存在就报告阻塞。」

AI 会先读范文与解剖笔记（没有就先补写），然后重写（不是直译），保留全部数字/限定条件，输出后自检（无残留中文、无全角标点、术语一致）。纯写作任务不必重做证据链。

### 示例 5：只用 M4 去 AI 味

> 「用 M4 精修这段英文，去 AI 味，不改研究含义：[粘贴段落]」

规则：只修空话、机械过渡词、破折号滥用、三点式堆砌；如果原文已合格，AI 应明确回复「保持原文」而不是表演式重写。

### 示例 6：只用 M5 评审一篇外部论文（最常用的独立场景）

**场景**：你是某篇工作论文的合作者/评论人，想要一套严格的评审意见。

> 「只用 M5 的 5.2：对附件这篇论文做模拟专家评审，3 位审稿人 + 编辑信，期刊水准对标《管理世界》。」

产出：`paper/{slug}/review/simulated-peer-review.md`。每位审稿人包含 Summary、编号的 Major/Minor Comments 和倾向判断，编辑信给出 2-3 个 deal-breaker。全程只攻击不代笔。

### 示例 7：拿到真实审稿意见后的返修（从 5.3 切入）

> 「从 M5 的 5.3 切入：这是《管理世界》的外审意见 [粘贴]。先结构化录入，和上次模拟评审的意见合并去重，给我 triage 清单等我裁决。」

你逐条裁决（必改/辩驳/标局限）后：

> 「按 triage 执行返修。意见 2 触及机制检验，回 M3 流程补一张中介表；其余走 M4 写作层。最后写 response letter。」

### 示例 8：单独跑一次 Referee 攻击（不进 M5）

**场景**：M3 里主回归方案定了，想在跑之前被攻击一轮。

> 「用 m5-referee-review 的 Mode A 攻击这份 PROPOSAL（重度级别，覆盖全部 5 维度）：[粘贴 proposal]」

产出 `paper/{slug}/discussions/ATTACK-001.md`，每条问题标 HIGH/MEDIUM/LOW。Researcher 在 `RESPONSE-001.md` 回应；Round 3 仍有 HIGH 时等待 `FINAL-VERDICT-001.md`。

### 示例 9：从 CSMAR 原始导出开始（M2 full_pipeline）

> 「跑 M2，m2_mode=full_pipeline。raw 下有股票月收益、财务指标和无风险利率三类导出；先做 intake-report 与 cleaning-plan，列出主键、频率、合并关系和预期 N，等我批准后再写脚本。」

正确顺序是 raw 清单 → intake-report → cleaning-plan 卡点 → `code/clean/` 一源一脚本 → `code/build/` 合并与筛选 → 样本侦查卡点 → 缺失处理/缩尾 → codebook/schema/双格式冻结。没有真实数据时，框架不会凭空生成可运行清洗代码。

### 示例 10：M3 资产定价（当前项目路线）

> 「从 M3 接手 a-share-multifactor-pricing。先核对 t-1 特征与 t 收益匹配、动量跳过最近一月、六月重排规则；输出 Portfolio Sort、Fama–MacBeth 和 GRS 的计划，等我批准。」

Python 分析脚本放 `code/analysis/{slug}/`，机器可读估计结果交给 `code/output/{slug}/` 生成表图。需要 `statsmodels`、`linearmodels` 和 `pyarrow`；由 `requirements.txt` 管理。每次规格都写 experiments 日志。

### 示例 11：只做 M5 内部审查（7R + 7Q）

> 「只跑 M5 5.1。先开独立 Referee 会话做 7R；完成后另开会话做 7Q。两份报告只提问题，不修改正文。」

产出 `review/logic-review-v1.md` 和 `review/quality-assessment-v1.md`。claim 审计也只输出 `review/claim-audit-v1.md`；registry 由后续 Researcher 根据你的裁决更新。

## 6. 知识库 paper-lib 使用指南

### 6.1 检索

```bash
# 验证索引路径对应的 PDF 是否都存在
python code/utils/check_paperlib.py

# 重建索引（PDF 有增删后执行一次）
python code/utils/paperlib_index.py --build

# 标题关键词检索（多个关键词 = AND）
python code/utils/paperlib_index.py --search 数字化 转型
python code/utils/paperlib_index.py --search 双重差分 --year 2024
```

PDF 被 gitignore，新 clone 只有索引和说明。必须从项目负责人提供的受控存储同步 PDF；检查器通过后 AI 才能按路径读原文。

### 6.2 各模块怎么用它

| 模块 | 用法 |
|------|------|
| M1 | 文献搜索**第一站**；严苛五问前两问（"被做过了吗""只是换样本吗"）必须以检索结果为证据 |
| M3 | 检索同方法论文，核对基准规格、FE 选择、聚类层级、稳健性套路是否符合该刊惯例 |
| M4 | 选 2-3 篇最接近范文做解剖笔记再动笔；对齐《管理世界》标题/引言/表格惯例 |
| M5 | 7Q 的文献比对对象；模拟审稿人攻击强度按该刊已发表论文水准校准 |

### 6.3 引用铁律（`paper-lib/README.md` §三）

1. 只引用**直接相关**的论文，不凑数。
2. 引用的结论/系数/样本期必须**回 PDF 原文核对**，不凭标题或记忆转述。
3. 风格是"句式骨架复用"不是抄袭：借结构，换全部事实内容。
4. 知识库只读：不修改、不删除、不写入产出。

### 6.4 扩充知识库

新增期刊按 `期刊名/期刊名年份/` 目录惯例放入合法取得的 PDF，然后 `--build`。英文范文列表见 `paper-lib/journal-list.md`；`fetch_style_pdf.py` 只下载 Semantic Scholar 提供的开放 PDF，不绕过付费墙，下载失败时改用你有权访问的本地文件。

## 8. 程序层与数据规范

### 8.1 数据流（单向，不可逆行）

```
data/raw/（只读）──清洗──→ data/processed/ ──构建+筛选──→ data/final/ ──估计──→ results/
```

### 8.2 代码运行顺序

```
code/config/  →  code/clean/  →  code/build/  →  code/analysis/{project-slug}/  →  code/output/{project-slug}/
```

当前 `scripts/master_build.py` 是**就绪检查器**，不执行任何阶段：

```bash
python scripts/master_build.py           # 生成 readiness 日志，始终可用于诊断
python scripts/master_build.py --strict  # 有缺失数据/脚本时退出码 1，适合 CI
```

`master_build.do` 的 clean/build/analysis/output 调用目前也只是注释示例。只有把真实项目脚本显式接入后，才能称为一键复现。

### 8.3 五条硬规范

1. **路径不硬编码**：Stata 用 `config.do` 全局宏（`$raw` `$final` `$tables` `$paperlib`…）；Python 用 `config.py` 的 `PATHS` 字典。
2. **日志强制**：每个 do 文件开头 `log using "$logs/脚本名.log", replace`。
3. **编号即顺序**：`01_`、`02_` 前缀反映执行顺序。
4. **头部三行注释**：输入文件 / 输出文件 / 功能说明（估计脚本另加包搜索结果）。
5. **双格式导出**：final 样本同时存 `.dta` + `.parquet`，跑 `validate_schema.py` 验证。

### 8.4 验证工具速查

```bash
python code/utils/validate_schema.py data/final/<样本>.parquet  # 需 schema.yaml
python code/utils/track_n_change.py       # 汇总各步骤样本量变化
python code/utils/validate_claims.py      # claim-证据链接完整性
python code/utils/experiment_summary.py   # 实验日志汇总
python code/utils/check_table_fonts.py    # 表格 .tex 字体一致性
python code/utils/dependency_check.py --list  # 脚本依赖关系
python code/utils/check_paperlib.py       # 索引与本地 PDF 一致性
```

`dependency_manifest.yaml` 初始为空；只有稳定脚本登记 output→script→inputs 后，依赖检查才会返回实际 DAG。`validate_claims.py` 对空 registry 发出警告，不等于已有 claim 通过验证。

### 8.5 当前仓库能做什么、不能做什么

当前可直接使用：

- M1/M2/M3/M4/M5 的路由、卡点、模板和 Cursor Skills；
- paper-lib 索引、PDF 就绪检查、Schema/claim/依赖/实验日志工具；
- Python 资产定价依赖、R 安装脚本、TeX 工具链和 MCP 配置样例；
- `master_build.py` 的就绪诊断。

当前尚未具备：

- CSMAR 原始数据和最终分析样本（这些也不应提交 Git）；
- 当前项目的 clean/build/analysis/output 可执行脚本；
- 自动执行四阶段的 master pipeline；
- 当前论文的主 `.tex` 文件和已生成结果。

因此，新 clone 可以运行框架和检查器，但不能在没有数据与项目脚本的情况下复现论文结果。输入未提供时 M2 保持 `not_started`；只有样本侦查报告已落盘并等待缺失处理裁决时，才使用 `blocked_on_human`。

## 9. 状态管理与跨会话接手

### 9.1 状态文件

| 文件 | 内容 | 谁更新 |
|------|------|--------|
| `system/metadata.md` | 当前模块、paradigm/engine、各模块状态、当前卡点 | AI 在模块收尾时回写 |

| `system/experiments.jsonl` | 每次估计的结构化记录；干净克隆中不存在，首次 M3 实验时创建 | Researcher 每次实验后追加 |

`system/experiments.schema.json` 是提交到仓库的字段约束；`system/experiments.jsonl`
是运行时研究记录。汇总工具在尚无实验记录时会明确跳过，不应把“文件未预置”误判为安装失败。

### 9.2 模块状态机

`not_started` → `in_progress` → `blocked_on_human`（等你裁决）→ `in_progress` → `done`
外部输入用 `done(external)`，模板补桩用 `done(stub)`，部分完成用 `done(partial)`。

### 9.3 新会话怎么无缝接手

新开一个 AI 会话时说：

> 「读 ORCHESTRATOR.md 和 system/metadata.md，接手当前进度。」

因为所有交接都走文件，新会话还应读取当前模块的 MODULE.md 和对应 `.cursor/skills/` Skill。`blocked_on_human` 时先找当前卡点记录，不能自行继续。

### 9.4 claim 状态词表（与 `validate_claims.py` 一致）

`unsupported`（仅主张）→ `theoretical`（有理论）→ `empirical_pending`（实证中）→
`empirically_supported`（已支撑）/ `fragile`（规格敏感，写作须弱化）/ `refuted`（被推翻，不得进正文）

## 10. 攻防协议：怎么用 Referee

### 10.1 标准循环

```
Researcher 写 PROPOSAL（含拓展思考）
  → Referee 写 ATTACK（按级别覆盖维度，问题标 HIGH/MEDIUM/LOW）
  → Researcher 写 RESPONSE（每条三选一：改 / 辩 / 标局限）
  → 你裁决 → 批准执行
  → Researcher 执行 → 记录 → Referee 审计结果
```

四类文件统一放在 `paper/{slug}/discussions/`：`PROPOSAL-001.md`、`ATTACK-001.md`、`RESPONSE-001.md`、`FINAL-VERDICT-001.md`。

### 10.2 什么任务需要多重攻防

| 级别 | 覆盖 | 轮次上限 | 典型任务 | 是否开独立 Referee 会话 |
|------|------|---------|---------|------------------------|
| 重度 | 5 维度全量 | 3 | 识别策略、主回归、证据链、正式审稿 | **是**（保证独立性） |
| 中度 | 前 3 维 + 聚焦 | 2 | 变量构造、诊断解读、章节草稿 | 可选 |
| 轻度 | 快速扫 | 1 | 表格格式、命名、编译修复 | 否（主会话自审） |

### 10.3 对 Referee 的质量要求（你验收时看这几点）

- 每条攻击**具体到变量、假设、步骤**——"可能存在内生性"这种不定位的批评应退回；
- 覆盖了全部应覆盖维度（找不到漏洞要写"该维度未发现实质问题"）；
- 语气严格中性，没有"总体而言这是扎实的研究"式平衡语；
- 没有伪造攻击点（不确定的标 LOW）。

## 11. 从服务器迁移到本地原生环境

本章以最常见的目标环境 **Windows 10/11 + Cursor + PowerShell** 为主，整个流程不需要 WSL2、Docker 或虚拟机。核心原则是：

1. **迁移项目内容，不迁移服务器运行环境**：源码、规则、Skills、数据、论文库和状态文件可以复制；Linux 的 Python 虚拟环境、R/TeX 可执行文件不能在 Windows 使用。
2. **本机重新安装工具链**：Python、R、TeX Live、Stata/MATLAB（可选）均使用原生 Windows 版本。
3. **共享配置保持可移植，本机路径只写入本地配置**：不要把 `D:/...` 写死到共享脚本；工具路径集中写入已被 Git 忽略的 `config/local-tools.json`，MCP 路径写入 `.cursor/mcp.json`。旧版 `stata_mcp_config_local.py` 仅为兼容入口。
4. **先迁移、再校验、最后删除服务器副本**：在本机完成文件数、数据、PDF、环境和 MCP 验证之前，不要清理服务器。

### 11.1 先识别哪些内容必须迁移

如果用压缩包复制整个 `Empirical-Economics-Agent/`，下面内容会一起迁移。如果只用 `git clone`，Git 忽略的内容不会出现，必须另行复制。

| 内容 | 是否通常由 Git 跟踪 | 本地是否需要 | 处理方式 |
|------|--------------------|--------------|----------|
| `.cursor/skills/`、`.cursor/rules/` | 是 | 必须 | Git 或压缩包 |
| `modules/`、`agents/`、`system/`、`scripts/`、`code/` | 是 | 必须 | Git 或压缩包 |
| `paper/{slug}/` 的正文与审查文件 | 通常是 | 必须 | Git 或压缩包 |
| `data/raw/`、`data/processed/`、大部分 `data/final/` | 否 | 做实证时必须 | 单独安全复制；可能含受限数据 |
| `results/tables/`、`results/figures/`、`results/logs/` | 否 | 建议保留 | 单独复制，便于核对服务器结果 |
| `paper-lib/**/*.pdf` | 否 | 使用本地知识库时必须 | 单独复制；仅有 `index.csv` 不等于 PDF 已迁移 |
| `paper/exports/*.docx` | 否 | 需要保留交换稿时复制 | 单独复制 |
| `config/local-tools.json`、`.cursor/mcp.json`、`*_local.py` | 否 | 不应原样复用 | 在本机重新生成，因为绝对路径已变化 |
| 服务器 `tools/`、`py_env/`、`.venv/` | 否 | **不要复制** | 本机重装 |
| `__pycache__/`、`*.pyc`、LaTeX 临时文件 | 否 | 不需要 | 排除 |

> 数据许可优先于技术便利。CSMAR、Wind 等受许可约束的数据只能通过符合授权协议的方式迁移，不要上传到公开 Git 仓库、公共网盘或无权限的共享空间。

### 11.2 推荐目录与路径规则

Windows 建议放在短、稳定、无中文且无特殊字符的目录，例如：

```text
D:\research\Empirical-Economics-Agent
```

尽量避免：

```text
C:\Users\姓名\OneDrive - 某机构\桌面\实证经济学智能体
```

原因不是 Cursor 无法处理中文，而是 Stata、部分 R 编译工具、TeX、旧版命令行程序及同步盘的占用锁更容易出问题。项目可以放在非系统盘，但不要频繁移动；MCP 配置中使用的是绝对路径，移动后要同步修改。

### 11.3 迁移方式 A：打包整个项目（最完整，推荐）

这种方式能保留被 `.gitignore` 排除的数据、PDF 和结果。先在服务器项目父目录执行：

```bash
cd /home/agent/research-agent
tar \
  --exclude='Empirical-Economics-Agent/.venv' \
  --exclude='Empirical-Economics-Agent/__pycache__' \
  --exclude='Empirical-Economics-Agent/**/*.pyc' \
  -czf Empirical-Economics-Agent-transfer.tar.gz \
  Empirical-Economics-Agent
sha256sum Empirical-Economics-Agent-transfer.tar.gz
```

说明：

- 默认会包含项目内的 `.git/`（如果存在），因此能保留提交历史和当前工作区状态；
- 不会包含位于项目外层的服务器 `tools/`，这正是需要的；
- 若数据量很大，先运行 `du -sh Empirical-Economics-Agent` 和 `du -sh Empirical-Economics-Agent/data Empirical-Economics-Agent/paper-lib` 估算体积；
- 压缩包可能含受限数据，下载完成后应妥善保存或删除，不要公开分享。

Windows 已启用 OpenSSH Client 时，在本机 PowerShell 下载：

```powershell
New-Item -ItemType Directory -Force D:\research | Out-Null
scp <服务器用户名>@<服务器地址>:/home/agent/research-agent/Empirical-Economics-Agent-transfer.tar.gz D:\research\
scp <服务器用户名>@<服务器地址>:/home/agent/research-agent/Empirical-Economics-Agent-transfer.tar.gz.sha256 D:\research\
```

如果没有单独生成 `.sha256` 文件，可在服务器执行：

```bash
sha256sum Empirical-Economics-Agent-transfer.tar.gz > Empirical-Economics-Agent-transfer.tar.gz.sha256
```

在 Windows 校验并解压：

```powershell
Set-Location D:\research
Get-FileHash .\Empirical-Economics-Agent-transfer.tar.gz -Algorithm SHA256
tar -xzf .\Empirical-Economics-Agent-transfer.tar.gz
Set-Location .\Empirical-Economics-Agent
```

将 `Get-FileHash` 的值与服务器 `sha256sum` 输出逐字符比较。校验不一致时不要继续使用，重新传输。若本机没有 `scp`，可用支持 SFTP 的客户端；传输协议不同不影响后续步骤。

### 11.4 迁移方式 B：Git 克隆 + 受忽略文件单独复制

### 11.8 Windows 配置 Stata MCP

以下二选一，不要同时启用两个同名/同用途的 Stata 服务器。
通用模板为 `scripts/mcp/mcp.json.example`；外部 Stata/MATLAB 服务器优先从
`scripts/mcp/mcp.windows.json.example` 复制配置。

#### 方案 A：仓库内置最小 Stata MCP

先把 Stata CLI 写入统一的本机配置：

```powershell
python .\scripts\configure_local.py `
  --stata-cli "C:/Program Files/Stata19/StataMP-64.exe"
```

路径以本机实际版本为准；旧版 `stata_mcp_config_local.py` 仍兼容。然后复制通用 MCP 示例：

```powershell
New-Item -ItemType Directory -Force .\.cursor | Out-Null
Copy-Item .\scripts\mcp\mcp.json.example .\.cursor\mcp.json
```

把 `.cursor/mcp.json` 简化为只保留内置服务器，例如：

```json
{
  "mcpServers": {
    "stata-builtin": {
      "command": "D:/research/Empirical-Economics-Agent/.venv/Scripts/python.exe",
      "args": [
        "D:/research/Empirical-Economics-Agent/scripts/mcp/stata_mcp_server.py"
      ]
    }
  }
}
```

JSON 中使用正斜杠可避免反斜杠转义。重启 Cursor 或重新加载窗口后查看 MCP 状态，再让 Agent 运行一条无数据命令，例如显示 Stata 版本。输出日志应落到 `results/logs/`。

#### 方案 B：MCP-for-Stata

先在已激活的 `.venv` 中安装 `uv`，确认 `uvx` 可用：

```powershell
python -m pip install uv

```

按 `ENVIRONMENT.md` 指向的 MCP-for-Stata 官方说明完成 Stata 端安装，并使用不低于文档要求的安全版本。手工配置时必须同时给出 Stata CLI 与仓库工作目录：

```json
{
  "mcpServers": {
    "stata-mcp": {
      "command": "D:/research/Empirical-Economics-Agent/.venv/Scripts/uvx.exe",
      "args": ["stata-mcp"],
      "env": {
        "STATA_CLI": "C:/Program Files/Stata19/StataMP-64.exe",
        "STATA_MCP__CWD": "D:/research/Empirical-Economics-Agent"
      }
    }
  }
}
```

实际 `uvx.exe` 路径可用 `Get-Command uvx | Select-Object -ExpandProperty Source` 查询，不要照抄示例猜路径。

## 12. 当前 Cursor 架构与 Claude Code 多 Subagent 架构

先区分两个容易混淆的概念：

- **Claude Code** 是一种 Agent 运行环境，本身也可以读取规则、调用 MCP、启动子代理；
- `discussions/V3.0-autoscientists-study.md` 讨论的是更具体的 **Claude Code 主循环 + ClawInstitute 协调层 + 多个 Subagent** 的长时间自治架构。

所以本节比较的是“本项目当前实现”与“早期讨论中的 AutoScientists 式多 Agent 实现”，不是断言 Cursor 和 Claude Code 产品本身只能采用某一种方式。当前 Cursor 也可以按需启动 Subagent；两者并非互斥。

### 12.1 当前框架为什么选择 Cursor 原生底座

当前调用链是：

```text
Cursor 主会话
  → .cursor/rules/ 自动加载底线与路由
  → ORCHESTRATOR.md + system/metadata.md 确定状态
  → MODULE.md 定义思维框架与输入/输出契约
  → .cursor/skills/ 提供可执行步骤
  → Python/R/TeX 或 Stata/MATLAB MCP 执行工具任务
  → 人类 Lead Author 在卡点裁决
```

它的优势：

1. **符合实证研究决策结构**：变量构造、缺失处理、识别假设、主结果解释不能只靠 Agent 投票，Lead Author 保留最终裁决。
2. **基础设施轻**：没有额外的 Workshop 服务、任务队列和多 Agent 锁；迁移到另一台机器只需项目文件、Cursor 和科研工具链。
3. **状态可审计**：决策、实验、claim 和模块状态落在仓库文件中，不依赖某个模型会话的隐藏记忆。
4. **模块可独立使用**：M2 样本审计、M4 写作、M5 外部论文评审均可单独运行。
5. **模型不绑定**：项目入口是 Cursor Agent，底层模型由会话选择；仓库没有 DeepSeek/Claude/OpenAI API 调用代码。
6. **工具边界清楚**：Skills 决定怎么做，MCP 只负责调用 Stata/MATLAB，研究状态仍由项目文件管理。

它的局限：

1. 主会话同时承担协调和大量执行时，Researcher 与 Referee 的独立性较弱；
2. 大量稳健性规格默认串行，速度可能慢；
3. 长时间无人值守任务需要额外监控，不能只靠文档假定自动恢复；
4. 同一上下文过长时，仍必须依靠 `metadata.md` 和落盘产出防止信息漂移。

### 12.2 Claude Code + 多 Subagent 的优势与成本

早期架构适合把任务拆给 Monitor、Analyst、执行 Agent，并通过共享工作区通信。主要优势：

1. **并行搜索能力强**：可同时跑不同稳健性、安慰剂、样本窗口或文献审查维度；
2. **角色隔离更真实**：Referee 不读取 Researcher 的推理上下文，更容易形成独立攻击；
3. **适合长时间自治实验**：任务认领、超时释放、KEEP/DISCARD 和结构化日志可以支持数小时运行；
4. **探索覆盖更广**：多个 Analyst 可从不同假设出发，降低单一会话过早收敛的风险。

相应成本：

1. **协调复杂**：需要任务队列、并发锁、去重、失败恢复和结果合并；Agent 数量增加不等于研究质量线性提高；
2. **费用和上下文消耗高**：每个 Agent 都要加载项目背景，重复阅读和重复实验不可避免；
3. **容易产生规格搜索风险**：若把“冠军模型”理解为显著性最高的模型，会滑向 p-hacking；经济学研究必须预先冻结估计计划；
4. **文件冲突风险高**：多个 Agent 同时修改 `metadata.md`、claim registry、正文或同一结果目录时需要严格写权限；
5. **人类控制点更难执行**：自治循环若没有强制门控，可能越过样本处理、识别策略和结果解释等人工卡点；
6. **本地维护要求更高**：除科研工具链外，还要维护协调服务、并发任务和运行监控。

### 12.3 本项目的推荐混合模式

本项目不需要在两套架构之间二选一。推荐以当前 Cursor 架构为控制面，只在收益明确的环节使用少量独立 Subagent：

| 环节 | 默认方式 | 何时使用 Subagent |
|------|----------|-------------------|
| M1 研究主题、范式和贡献定位 | 主会话 + 人裁决 | 可并行做不同文献簇检索，但不能让投票替代 Lead Author |
| M2 样本侦查 | 主会话顺序执行 | 可并行检查不同数据源；任何清洗决策仍须停在卡点 |
| M3 估计计划与主回归 | 主会话，先批准后执行 | 不建议并行探索主规格 |
| M3 稳健性与诊断 | 批准矩阵后执行 | 最适合 2–3 个只读输入、分目录输出的执行 Subagent |
| M4 论文写作 | 主会话维护唯一正文 | 可让只读 Subagent 查证引用或审查表图，避免多人同时改正文 |
| M5 正式模拟评审 | 独立 Referee 会话 | 推荐 1–2 个互不共享上下文的 Referee，主会话只汇总 |

多 Subagent 必须遵守四条附加规则：

1. **先冻结任务矩阵**：每个 Agent 的规格、输入、输出和停止条件事先写清；
2. **输入只读、输出隔离**：不同 Agent 不修改同一文件，结果写入独立子目录或独立报告；
3. **禁止以显著性选冠军**：比较标准来自预注册识别逻辑、诊断和稳健性，而不是 p 值最大；
4. **统一回收与人工裁决**：主会话汇总冲突，但 Lead Author 决定采纳，不允许 Agent 投票自动改主结果。

### 12.4 怎么选择

采用当前 Cursor 单主会话架构，如果任务具有以下特征：

- 研究设计尚未冻结，需要频繁与 Lead Author 讨论；
- 数据敏感，不适合复制到多个执行环境；
- 只运行一个模块或一次短任务；
- 重点是可审计、可接手和工具集成，而不是搜索吞吐量。

在当前架构上增加少量 Subagent，如果：

- M3 估计矩阵已获批准，任务间彼此独立；
- 需要独立 Referee，避免主会话自我确认；
- 单任务运行时间长，但输出契约清楚且可以分目录；
- 有能力检查成本、重复任务、写冲突和失败恢复。

只有在需要持续数小时到数天的大规模假设搜索、且已经具备任务队列和监控能力时，才值得考虑完整的 Claude Code + 协调层 + 多 Subagent 架构。对一般实证论文，10 Agent 式系统通常增加的是运维和审计负担，而不是识别可信度。

## 13. 常见问题排查（FAQ）

**Q1：`python` 命令找不到？**
macOS/Linux 先运行 `source scripts/setup_env.sh`；Windows 本机从仓库根点调用 `. .\scripts\setup_env.ps1`。仍找不到时用 `py -0p`（Windows）或 `command -v python3`（macOS/Linux）检查解释器，并确认 `.venv` 已按 11.5 创建。

**Q2：AI 说要缩尾/删缺失，我还没同意？**
这是违规。回复「停止，先给我 M2 样本侦查报告」。样本侦查先于任何处理是不可违反规则第 3 条。

**Q3：没有 Stata 怎么跑 DID？**
先运行 `Rscript scripts/install_r_packages.R`，再用 `fixest::feols`、`did` 或 `rdrobust`。只安装 R 可执行文件不代表这些包已就绪。

**Q4：paper-lib 检索不到我要的主题？**
索引只匹配标题。换关键词（如"工具变量"在标题中少见，试方法+主题组合词）；或确认已 `--build` 重建索引；标题检索不到不代表没有相关文献，仍需 Zotero/Google Scholar 补充。

**Q5：中文 LaTeX 编译乱码/报错？**
用 `xelatex`（不是 pdflatex）+ ctex 宏包。Linux 服务器运行 `which xelatex`；Windows 运行 `Get-Command xelatex` 和 `kpsewhich ctex.sty`。命令不存在时检查 TeX Live 的二进制目录是否进入 `PATH`。

**Q6：想跳过某个卡点赶进度？**
卡点不可跳过（规则 8）。但轻量路径存在：方式 B/C 切入时上游可以 stub；纯润色任务不必重做证据链。卡点本身（范式/缺失/估计计划/结果/证据链/章节/返修）必须过人。

**Q7：docx 里合作者的批注怎么处理？**
人工判断后同步回 `paper/{project-slug}/sections/*.tex`。docx（`paper/exports/`）不是论文真源，直接改 docx 的内容会丢失。

**Q8：如何验证"正文数字没有手输"？**
英文稿中的表格数字应全部经 `\input{results/...}` 引用；关键系数在 `system/claim-registry.json` 有证据链接，跑 `validate_claims.py` 核验。

**Q9：git 提交时报身份错误？**
这是 Git 用户身份未配置，不是框架错误。由仓库维护者按组织规范配置本地或全局身份；不要把临时占位身份写入共享配置。

**Q10：一个会话里能同时当 Researcher 和 Referee 吗？**
轻度任务可以（主会话自我攻防）；重度子步骤（识别策略、主回归、证据链、正式审稿）必须开独立 Referee 会话，且双 Referee 交叉验证时互不共享上下文。
