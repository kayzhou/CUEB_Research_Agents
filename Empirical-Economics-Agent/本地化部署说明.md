# 本地化部署说明 — Stata / MATLAB 双模式接入

> 对应框架版本：v1.2（2026-08-05）。
> 适用对象：在个人计算机（Windows / macOS / Linux 原生环境）部署本框架的使用者。
> 本文档在现有 **MCP 接入方案**（见 `ENVIRONMENT.md`、`使用手册.md` 第 7/11 章）的基础上，
> 新增 **本地直连模式**：本机已安装 Stata / MATLAB 时，不经 MCP 服务器，由 Agent 直接在终端以批处理方式调用。
> 两种模式二选一或并存均可，选定后登记到 `system/metadata.md`。
> 当前发布整改在 Linux 服务器完成；Windows/macOS 命令仍须按第六章在相应真机人工验收。

---

## 一、部署总览

### 1.1 两种接入模式

| | 模式 A：MCP 接入（现状默认） | 模式 B：本地直连（本文新增） |
|---|---|---|
| 原理 | 在 `.cursor/mcp.json` 注册 MCP 服务器，Agent 通过 `run_stata` 等 MCP 工具执行代码 | Agent 在终端直接调用本机 Stata / MATLAB 可执行文件，批处理运行脚本 |
| 前置条件 | 本机已安装 Stata/MATLAB，并配置 MCP 服务器 | 本机已安装 Stata/MATLAB，无需任何 MCP 配置 |
| 优点 | 交互粒度细，可执行代码片段并即时返回日志；日志落点由服务器统一管理 | 无需 MCP 组件；行为与手工运行 `.do` / `.m` 完全一致，复现路径直观 |
| 缺点 | 需维护 MCP 配置与服务器版本；配置变更后须重启 Cursor 或重新加载窗口方可生效 | 每次调用为完整批处理会话，无跨调用状态；需自行遵守日志落点规范 |
| 适合场景 | Agent 驱动的高频探索式分析（M3 反复试错阶段） | 已有成型脚本的正式运行、流水线复跑，以及不便配置 MCP 的环境 |

两种模式**不互斥**：同一台机器可在探索阶段使用 MCP、在正式复跑时使用本地直连。但同一次估计的正式结果仅采用一种来源，并在写入 `system/metadata.md` 的 `engine` 字段时注明。

### 1.2 部署路线图

```
0. 先读 Windows / macOS 差异对照               → 本文 §2.2（避免误用其他平台的命令）
1. 基础工具链（Python / R / TeX Live）        → 按《使用手册》第 11 章完成，本文不重复
2. Stata   ├─ 走 MCP    → 本文 §3.1（指向现有文档）
           └─ 走本地直连 → 本文 §3.2 ★
3. MATLAB  ├─ 走 MCP    → 本文 §4.1（指向现有文档）
           └─ 走本地直连 → 本文 §4.2 ★
4. 登记与验收                                  → 本文 §5、§6
```

无 Stata / MATLAB 授权的机器不需要读 §3、§4：因果推断降级为 R 引擎，结构估计降级为 Python(scipy)，见 `ENVIRONMENT.md` 的引擎决策树。

## 二、基础环境与平台差异

### 2.1 前置清单（简要）

以下内容《使用手册》第 11 章已有完整步骤（11.5 Windows / 11.11 macOS），此处只列清单：

1. **Cursor** 打开**仓库根目录**（不能只打开子目录，否则 `.cursor/skills|rules|mcp.json` 不生效）。
2. **Python 3.10** 虚拟环境（本地建议建在仓库根 `.venv/`），安装 `requirements.txt`。
3. **R 4.4.x** + 四个因果推断包（`fixest` / `did` / `rdrobust` / `eventstudyr`），运行 `Rscript scripts/install_r_packages.R`。
4. **TeX Live**（英文 `pdflatex`、中文 `xelatex` + `ctex`）。
5. 首次运行 `python scripts/configure_local.py` 生成本机路径配置；Windows 点调用 `. .\scripts\setup_env.ps1`，macOS/Linux 执行 `source scripts/setup_env.sh`。

### 2.2 Windows 与 macOS 差异对照（必读）

后文所有命令都分 Windows / macOS 两套写法，差异集中在下表。**Linux 与 macOS 属同一套 Unix 写法**（仅安装路径不同），下表不再单列。

| 差异点 | Windows | macOS |
|---|---|---|
| 终端 / Shell | PowerShell：环境变量 `$env:VAR`；调用带空格路径的程序要加 `&` 运算符；续行符是反引号 `` ` ``；重定向全部输出用 `*>` | 默认 zsh（bash 同理）：环境变量 `export VAR=...`；带空格路径加引号即可；续行符 `\`；重定向用 `> file 2>&1` |
| 环境变量持久化 | 写入个人激活脚本（如 `$HOME\Documents\eea-env.ps1`，每次打开终端后先执行），或写入系统"环境变量"设置 | 写入 `~/.zshrc`（macOS 默认 shell 为 zsh，**而非** `~/.bashrc`），保存后执行 `source ~/.zshrc` 生效 |
| Stata 可执行文件位置 | 独立 `.exe`，位于安装目录下直接可见：`C:/Program Files/Stata19/StataMP-64.exe` | 位于 **`.app` 程序包内部**（Finder 中需右键「显示包内容」方可查看），批处理应使用其中的**命令行程序**（小写，如 `stata-mp`）：`/Applications/Stata/StataMP.app/Contents/MacOS/stata-mp` |
| Stata 批处理参数 | `/e do`（批处理运行，不弹出窗口与完成提示） | `-b do` |
| Stata 日志编码 | 中文 Windows 环境常为 **GBK**，直接打开可能乱码（见 §七 Q2） | UTF-8，一般无乱码问题 |
| MATLAB 可执行文件位置 | `C:/Program Files/MATLAB/R2026a/bin/matlab.exe` | 同样位于 `.app` 包内：`/Applications/MATLAB_R2026a.app/bin/matlab` |
| 路径写法 | 终端中反斜杠、正斜杠均可；但 **Stata do 文件与 JSON 配置内一律使用正斜杠 `/` 并加双引号**（含盘符的路径不加引号会被 Stata 解析为命令） | 原生正斜杠，无盘符，天然满足该规则 |
| Python venv 激活 | `.\.venv\Scripts\Activate.ps1`（首次需 `Set-ExecutionPolicy -Scope Process Bypass`） | `source .venv/bin/activate` |
| 下载的 MCP 二进制（模式 A） | `.exe` 下载后即可使用 | 先以 `uname -m` 确认 Apple Silicon `arm64` 或 Intel `x86_64` 并下载匹配架构；执行 `chmod +x`；若 Gatekeeper 隔离，在确认来源后用 `xattr -d com.apple.quarantine /path/to/matlab-mcp-server` 或在“隐私与安全性”中放行 |
| `uvx` 路径（模式 A，使用 MCP-for-Stata 时） | `.venv\Scripts\uvx.exe` | `.venv/bin/uvx` |

小结：Windows 的高频问题集中在**路径引号、`/e` 参数、GBK 编码**三处；macOS 的高频问题集中在 **CLI/GUI 路径、CPU 架构、Gatekeeper 放行**三处。

## 三、Stata 部署

### 3.1 模式 A：MCP 接入（现状方案，指引）

保持不变，配置方法不在本文重复：

- **开源方案（推荐）**：[SepineTam/mcp-for-stata](https://github.com/SepineTam/mcp-for-stata)（≥ v1.17.3）或 [hanlulong/stata-mcp](https://github.com/hanlulong/stata-mcp) → 见 `ENVIRONMENT.md` 第二节。
- **仓库内置最小实现**：`scripts/mcp/stata_mcp_server.py` → 优先从 `config/local-tools.json` 读取 Stata CLI（旧版 `stata_mcp_config_local.py` 仍兼容）；客户端通用模板见 `scripts/mcp/mcp.json.example`，分平台模板见同目录 `mcp.windows|macos|linux.json.example`。

### 3.2 模式 B：本地直连（新增选项）

本机已安装并激活 Stata 时，无需任何 MCP 配置，直接使用 Stata 的**批处理模式**运行 `.do` 文件。

#### 第 1 步：确认本机 Stata 可执行文件路径

| 平台 | 典型路径（以本机实际版本为准） |
|---|---|
| Windows | `C:/Program Files/Stata19/StataMP-64.exe` |
| macOS | `/Applications/Stata/StataMP.app/Contents/MacOS/stata-mp` |
| Linux | `/usr/local/stata19/stata-mp` |

平台注意点：

- **Windows**：文件名随授权版本为 `StataMP-64.exe` / `StataSE-64.exe` / `StataBE-64.exe`，位于安装目录下直接可见。
- **macOS**：可执行文件位于 `.app` 包内部的 `Contents/MacOS/` 目录下，该目录同时包含**图形界面程序**（与 `.app` 同名，如 `StataMP`）和**命令行程序**（小写带连字符，如 `stata-mp` / `stata-se`，BE 版为 `stata`）。批处理模式应使用**命令行程序**，以图形界面程序运行批处理可能唤起 GUI。可在终端执行 `ls /Applications/Stata/*.app/Contents/MacOS/` 确认实际文件名。

首次安装后须手工启动一次 Stata 完成授权，再执行后续步骤。

#### 第 2 步（推荐）：登记本机路径并激活

首次配置可让生成脚本写入统一的本机文件：

```bash
python scripts/configure_local.py \
  --stata-cli "/Applications/Stata/StataMP.app/Contents/MacOS/stata-mp"
source scripts/setup_env.sh
```

```powershell
python .\scripts\configure_local.py `
  --stata-cli "C:/Program Files/Stata19/StataMP-64.exe"
. .\scripts\setup_env.ps1
```

脚本写入被 Git 忽略的 `config/local-tools.json`，激活时将 `stata_cli` 映射为
`EEA_STATA_EXE`。若配置已存在，直接编辑其中的 `stata_cli` 字段，避免用 `--force`
覆盖其它手工路径。环境变量仍可临时覆盖本机配置，但本机绝对路径**不得**写入共享文件。

#### 第 3 步：批处理运行 do 文件

关键约定：**始终从仓库根目录运行**。`code/config/config.do` 以当前工作目录为项目根自动推导全部路径（`$raw`、`$final`、`$tables`、`$logs` 等），从仓库根运行即无需修改任何路径配置。

```bash
# macOS / Linux —— 在仓库根执行（参数为 -b）
cd /path/to/Empirical-Economics-Agent
"$EEA_STATA_EXE" -b do "code/analysis/a-share-multifactor-pricing/xxx.do"
```

```powershell
# Windows PowerShell —— 在仓库根执行（参数为 /e，路径变量前须加 & 调用运算符）
Set-Location D:\research\Empirical-Economics-Agent
& $env:EEA_STATA_EXE /e do "code/analysis/a-share-multifactor-pricing/xxx.do"
```

说明：

- **批处理参数是两平台最易混淆的差异**：Windows 使用 `/e`，macOS/Linux 使用 `-b`；与内置 MCP 服务器 `stata_mcp_server.py` 内部的调用方式一致。
- **PowerShell 语法**：程序路径存于变量或含空格时，前面必须加 `&` 调用运算符，否则 PowerShell 会将其视为字符串输出而非执行。
- 批处理模式会在**当前目录**生成与 do 文件同名的 `.log`。规范要求正式日志落 `results/logs/`，因此正式脚本应在开头显式声明 `log using "$logs/xxx.log", replace text`（模板已如此）；仓库根残留的 `.log` 应及时删除，不得提交。
- do 文件内所有含盘符的路径必须加双引号、统一使用正斜杠（规则见 `config.do` 头部注释）；提交前运行 `python code/utils/check_stata_paths.py code/` 自查。

#### 第 4 步：在 Cursor 中告知 Agent 使用本地直连

本地直连模式无需重启 Cursor，也不依赖 MCP 服务器状态。新会话中直接说明即可，例如：

> 「本机 Stata 走本地直连：可执行文件路径见环境变量 `EEA_STATA_EXE`（或给出完整路径），请在终端从仓库根以批处理方式运行 do 文件，不要调用 Stata MCP 工具。」

建议同时将该说明写入 `system/metadata.md` 的环境备注（见 §5），跨会话接手时 Agent 可自动读取。

#### 第 5 步：验证

macOS / Linux：

```bash
# 在仓库根创建最小 do 文件并批处理运行
printf 'include "code/config/config.do"\ndisplay "root=$root"\ndisplay c(stata_version)\n' > _smoke.do
"$EEA_STATA_EXE" -b do _smoke.do
cat _smoke.log      # 应输出路径配置加载信息与版本号，且无报错
rm _smoke.do _smoke.log
```

Windows PowerShell：

```powershell
# 在仓库根创建最小 do 文件并批处理运行
# 使用 ASCII 编码写入，避免 UTF-8 BOM 干扰 Stata 解析首行
@'
include "code/config/config.do"
display "root=$root"
display c(stata_version)
'@ | Set-Content -Encoding ASCII _smoke.do
& $env:EEA_STATA_EXE /e do _smoke.do
Get-Content _smoke.log    # 若中文乱码，用支持 GBK 编码的编辑器打开（参见 §七 Q2）
Remove-Item _smoke.do, _smoke.log
```

输出中包含 `✓ 路径配置加载完成` 与 Stata 版本号，即视为部署成功。

### 3.3 如何选择

- 希望以最低配置成本运行、无需安装 MCP 组件 → **模式 B**。
- M3 阶段需要 Agent 高频执行代码片段并即时读回日志 → **模式 A**（片段执行不必落成 do 文件）。
- 尚未确定 → 先用模式 B（零配置），后续按需补配 MCP，两者互不冲突。

## 四、MATLAB 部署

### 4.1 模式 A：MCP 接入（现状方案，指引）

MathWorks 官方开源 [matlab/matlab-mcp-server](https://github.com/matlab/matlab-mcp-server)：从 Releases 下载对应平台二进制 → 在 `.cursor/mcp.json` 注册，设置 `--matlab-root=版本根目录` 和 `--initial-working-folder=仓库根目录`。优先使用 `scripts/mcp/mcp.windows.json.example`、`mcp.macos.json.example` 或 `mcp.linux.json.example`；通用模板 `mcp.json.example` 继续兼容。

平台差异：

- **Windows**：下载 `.exe` 后即可直接注册使用。
- **macOS**：先用 `uname -m` 区分 `arm64` 与 `x86_64` 并下载匹配架构；执行 `chmod +x`。若 Gatekeeper 隔离下载文件，在确认来源后执行 `xattr -d com.apple.quarantine /path/to/matlab-mcp-server`，或在“系统设置 → 隐私与安全性”中放行后重试。

### 4.2 模式 B：本地直连（新增选项）

本机已安装并激活 MATLAB（R2019a 及以上版本）时，直接使用 `matlab -batch` 无窗口运行脚本。

#### 第 1 步：确认可执行文件路径

| 平台 | 典型路径（以本机实际版本为准） |
|---|---|
| Windows | `C:/Program Files/MATLAB/R2026a/bin/matlab.exe` |
| macOS | `/Applications/MATLAB_R2026a.app/bin/matlab` |
| Linux | `/usr/local/MATLAB/R2026a/bin/matlab` |

#### 第 2 步（推荐）：登记本机路径并激活

`local-tools.json` 保存 MATLAB 版本根目录（不含 `bin`）；激活脚本据此导出
`EEA_MATLAB_ROOT` 和 `EEA_MATLAB_EXE`：

```bash
python scripts/configure_local.py \
  --matlab-root "/Applications/MATLAB_R2026a.app"
source scripts/setup_env.sh
```

```powershell
python .\scripts\configure_local.py `
  --matlab-root "C:/Program Files/MATLAB/R2026a"
. .\scripts\setup_env.ps1
```

配置已存在时直接编辑 `matlab_root` 字段，不要无意覆盖其它本机路径。

#### 第 3 步：批处理运行 .m 脚本

同样**从仓库根运行**，脚本输出统一写入 `results/`：

```bash
# macOS / Linux —— 运行 code/analysis/{slug}/ 下的脚本
cd /path/to/Empirical-Economics-Agent
"$EEA_MATLAB_EXE" -batch "addpath(genpath('code')); run('code/analysis/a-share-multifactor-pricing/xxx.m')" \
  > "results/logs/xxx_matlab.log" 2>&1
```

```powershell
# Windows PowerShell（& 调用运算符 + 反引号续行 + *> 重定向全部输出）
Set-Location D:\research\Empirical-Economics-Agent
& $env:EEA_MATLAB_EXE -batch "addpath(genpath('code')); run('code/analysis/a-share-multifactor-pricing/xxx.m')" `
  *> "results/logs/xxx_matlab.log"
```

说明：

- **`-batch` 参数两平台完全一致**（与 Stata 不同，无 `/e` 与 `-b` 之分）；差异仅在 shell 语法：重定向 macOS 用 `> file 2>&1`、Windows 用 `*>`；续行 macOS 用 `\`、Windows 用反引号 `` ` ``。
- `-batch` 自动包含无桌面、无欢迎屏，脚本出错时以非零退出码结束（便于 Agent 判断成败）；**不要**混用旧式 `-nodisplay -nosplash -r "...; exit"` 写法。
- MATLAB 没有与 `config.do` 对应的路径配置文件，脚本内路径一律写**相对于仓库根**的相对路径（如 `data/final/...`、`results/tables/{slug}/...`），因此必须从仓库根启动。
- 日志通过重定向写入 `results/logs/`，与 Stata 日志遵循同一落点规范。

#### 第 4 步：在 Cursor 中告知 Agent

> 「本机 MATLAB 走本地直连：使用 `EEA_MATLAB_EXE`（或完整路径）加 `-batch` 从仓库根运行 .m 脚本，日志重定向至 `results/logs/`，不要调用 MATLAB MCP 工具。」

#### 第 5 步：验证

```bash
# macOS / Linux
"$EEA_MATLAB_EXE" -batch "disp(version); disp(pwd)"
```

```powershell
# Windows PowerShell
& $env:EEA_MATLAB_EXE -batch "disp(version); disp(pwd)"
```

能正确输出版本号与当前目录（应为仓库根）即视为部署成功。

### 4.3 如何选择

MATLAB 在本框架中仅承担结构估计与数值优化（M3 的少数任务），调用频率低、多为整脚本运行，**多数情况下模式 B 已足够**；仅当需要 Agent 与 MATLAB 工作区进行细粒度交互（查看变量、分步执行）时，才需配置 MCP。

## 五、部署结果登记

部署完成后登记以下两处，确保跨会话、跨机器接手时 Agent 无需重复确认环境：

1. **`system/metadata.md`**：
   - `engine` 字段写明实际引擎（如 `stata`），并备注接入模式，例如：
     `engine: stata（本地直连，经 EEA_STATA_EXE）` 或
     `engine: stata（MCP: stata-builtin）`。
   - MATLAB 同理，仅在实际使用时登记。
2. **`config/local-tools.json`**：保存本机实际路径；该文件已被 gitignore，**不得提交**，也不要把绝对路径抄入 `system/metadata.md`。
3. **`.cursor/mcp.json`**（仅模式 A 需要）：只保留实际启用的服务器条目；该文件已被 gitignore，**不得提交**。模式 B 不需要此文件；两种模式并存时，不要注册两个同用途的 Stata 服务器。

估计脚本头部照常注明所用引擎与包版本（`ORCHESTRATOR.md` 既有规则，与接入模式无关）。

## 七、常见问题

**Q1：两种模式能否同时启用？**
可以。MCP 配置与本地直连互不干扰。但须注意：(1) 不要在 `.cursor/mcp.json` 中注册两个同用途的 Stata 服务器；(2) 同一张正式表格的生成路径仅采用一种来源，并在脚本头部注明，避免复现歧义。

**Q2：本地直连时 Stata 日志出现乱码，如何处理？**
中文 Windows 环境下 Stata 日志通常为 GBK 编码。用支持编码切换的编辑器打开，或让 Agent 按 UTF-8 → GBK → GB18030 顺序尝试解码（内置 MCP 服务器即按此顺序处理）。

**Q3：批处理运行报 `command C is unrecognized` 类错误，是什么原因？**
通常由含盘符的路径未加双引号导致。规则见 `code/config/config.do` 头部注释；运行 `python code/utils/check_stata_paths.py code/` 可批量自查。

**Q4：`matlab -batch` 提示找不到函数或脚本，如何排查？**
确认从仓库根目录启动，且命令中已包含 `addpath(genpath('code'))`。`-batch` 的工作目录即启动时的当前目录，不会自动切换。

**Q5：已安装 Stata 但暂不进行任何配置，Agent 能否使用？**
可以。在对话中给出 Stata 完整路径并要求以批处理方式运行即可。长期使用时把路径写入被忽略的 `config/local-tools.json`；`system/metadata.md` 只登记引擎和接入模式，不登记本机绝对路径。

**Q6：本文档与 `ENVIRONMENT.md`、《使用手册》第 11 章是什么关系？**
`ENVIRONMENT.md` 登记工具链现状（以 MCP 为默认方案）；《使用手册》第 11 章是服务器 → 本地的完整迁移流程；本文档聚焦 Stata / MATLAB 的接入模式选择，新增本地直连选项。基础环境安装以手册第 11 章为准，本文不重复维护。
